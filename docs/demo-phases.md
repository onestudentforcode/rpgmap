# rpgmap 实验阶段规划

> **定位：实验沙盒。** 验证「tile 网格内核 + 确定性地图生成工作流」能否支撑两类复用场景。
> **daoyan 接入不是本阶段任务**——`docs/daoyan-reuse-plan.md`（含回执决议）仅作背景输入
> 与将来移植备忘，本实验不读改 daoyan 任何代码。
> **ComfyUI 不在本机**：正式美术为跨机器协作，本机只负责规格制定、清单产出、
> 占位图生成与 QC 验收。

## 1. 背景输入（只读参考，不构成实施内容）

- `docs/daoyan-reuse-plan.md` + `docs/daoyan-reuse-plan-answers.md`：定义内核将来要兼容的
  目标形态——JSON 内容包、功能入口式交互（SceneCommand 雏形）、地图只抛事件的战斗触发、
  写即存式状态、engine/app 分层。
- 复用场景一：**星露谷式城镇**——多个城镇共享同一内核，单镇由多张功能地图组成，
  含特殊交互点，镇间靠主题数据变化。
- 复用场景二：**野外图**——自身不承载战斗逻辑，只作为战斗触发器。
- 已有基础：MVP 内核（todo.md，P0 已完成）+ 占位美术管线 + 自测/截图验收基建。

## 2. 实验要证明的事（内核需求 R1–R9）

| # | 需求 | 来源 | 验证落点 |
|---|------|------|----------|
| R1 | 确定性：同一源数据 bake 两次产物逐字节一致；运行时永不生成 | 两场景共用 | P1 |
| R2 | 数据/代码分离：新增或修改地图零代码改动 | 城镇量产 | P1 |
| R3 | 主题包换肤：同一布局换 JSON+贴图即成另一城镇 | 多城镇 | P2 |
| R4 | 门户图：单镇多张功能地图连通且空间连贯 | 城镇 | P1/P3 |
| R5 | 类型化交互点：六种类型各有行为；menu 型可挂功能入口 | 城镇特殊交互点 | P3 |
| R6 | 被动战斗触发：地图只抛事件，战斗在地图之外 | 野外 | P4 |
| R7 | 一次性状态：消费型交互跨图持久，留存档接缝 | 宝箱/清怪 | P3/P4 |
| R8 | 美术回填：manifest 驱动跨机器产出 → 本机 QC → 零代码替换 | 美术量产 | P5 |
| R9 | 质量基建：自测+截图验收随内核一起演进 | 全部 | 贯穿 |

## 3. 阶段

### P0 内核 MVP（已完成，@017a09c）

tile 地图 + 行走精灵 + 交互对话 + 双地图切换 + 占位资产 + 自测/截图基建。
当前为 GDScript 常量源数据 + 运行时构建（工作流改造前的形态）。

### P1 工作流改造：数据外置 + 烘焙管线（核心阶段）✅ 已完成

**目标**：地图从「代码常量」变为「JSON 源数据 → bake → 规范化产物 + 资产清单 → 运行时加载」。

- [x] 源数据 schema：`content/maps/*.json`——ASCII 布局字符串数组、图例→图块映射、
      传送表（双向）、交互点注册表、氛围文本（schema 说明见 `docs/map-schema.md`）
- [x] bake 工具（`tools/bake_maps.py`，Python 实现）：校验（图例覆盖/传送对称/
      出生格合法/引用存在）→ 规范化 JSON（`content/baked/<theme>/maps/`）→ **manifest 资产清单**
      （该图用到的图块/物件/帧，含尺寸与用途，即美术采购单）
- [x] MapHost（`scripts/map_host.gd`）：运行时只读规范化产物构建地图，
      `map_data.gd` / `map_builder.gd` 常量路径已删除
- [x] 交付：bake 工具、schema 说明、迁移后的现有两张地图

**验收**：
- [x] bake 两次产物 diff 为空（R1 确定性，md5 级验证）
- [x] 新增第三张测试图（储物间）：只加 JSON 文件，零脚本改动，门户互通（R2/R4）
- [x] 既有自测改造后全过（R9，17 项）
- [x] manifest 与地图实际引用一致（自测以烘焙数据反查节点数验证）

**过程中修复的两个缺陷**：
1. 相机 limit 钳制不含 offset → 视口越出地图出现灰边；改为按 offset 反向平移 limit。
2. 占位行走图**右向整行是空帧**（生成器 `player_frame()` 缺 right 分支，镜像空画布），
   面朝右时角色整体消失；补镜像逻辑并在 QC 中增加逐行不透明度检查（防空帧漏检）。

### P2 主题包与换肤演练（小阶段）✅ 已完成

**目标**：证明「多城镇 = 多主题包」，布局与皮肤解耦。

- [x] 主题 JSON：`palette_overrides`（相对基准色板的覆盖）+ 贴图路径（按主题分目录
      `assets/themes/<id>/`），与布局数据分离
- [x] 第二套主题 `dusk`（暮色：薰衣草地面/李子墙/靛蓝地毯/墨绿大衣金围巾），
      同布局仅换色板；生成器读主题 JSON 逐主题出图
- [x] bake 改为**主题 × 地图全组合**（地图源数据不再声明主题；主题契约 = 覆盖全部
      语义图块/物件，逐主题校验）；启动 `--theme=<id>` 选择主题
- [x] 交付：两套主题包 + 换肤说明（docs/map-schema.md §2）

**验收**：
- [x] 换主题 = 换 JSON+贴图，零代码改动（bake 6 张产物：2 主题 × 3 图，确定性保持）
- [x] 两主题截图各验一遍（10 张，玩家可见性逐张扫描；自测新增双主题布局一致性校验）

### P3 功能地图与类型化交互点

**目标**：单镇多张功能图 + 六种交互点类型体系。

- [ ] 类型注册表：`portal` / `dialogue`（纯氛围文本）/ `menu` / `chest` /
      `battle_trigger` / `save`（留位不实现）
- [ ] `menu` 型：靠近触发 → 弹出占位功能菜单（列出「商店/修炼/…」选项，选择仅展示
      说明文本）；**事件签名留接缝**（对齐背景中的功能入口分发形态，不实现对接）
- [ ] `chest`：一次性消费 + 跨图持久（内存级 + 接缝注释；本地 JSON 存档列为可选项）
- [ ] 单镇扩到 3 张功能图（hub/坊市/后院），门户表连通、空间连贯

**验收**：六类交互点各有可走通用例；跨图状态不丢；自测扩充覆盖新类型（R5/R7）。

### P4 野外战斗触发场景

**目标**：验证「地图只触发、不承载战斗」。

- [ ] 独立野外主题包（约 40×30，滚动地图）
- [ ] `battle_trigger` 明雷标记格：走进触发，默认冷却可重复，数据可声明一次性
- [ ] 战斗桩：全屏占位「战斗中」提示（可选极简回合占位）→ 结束返回原地图原位置
- [ ] 战后标记（已清怪/冷却中）随 R7 状态走

**验收**：进→战→回全链；位置与标记正确；野外门连回城镇 hub，门户互通（R6）。

### P5 美术回填演练（跨机器协作）

**目标**：跑通「manifest → ComfyUI 出图（他机）→ 本机 QC → 零代码替换」。

- [ ] 移交包：manifest + 资产规格（assets-spec.md 修订版）+ 逐资产提示词建议 + 命名尺寸表
- [ ] 本机切图/QC 工具（PIL 已就绪）：大图 → 规格图块、alpha/色板/尺寸检查
- [ ] 用正式图替换一张图的全部贴图，跑自测与截图验收

**验收**：替换后零代码/场景改动，验收通过（R8）。

### P6 结题：实验报告 + 移植备忘

## 4. 顺序与依赖

```
P0 ✅ → P1 → P2 → P3 → P4 → P5 → P6
```

- 每阶段收尾必须：自测全过 + 截图人工核对 + git 提交。
