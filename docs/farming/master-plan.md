# 一、项目背景与目标

## 1.1 业务背景

原有东方仙侠游戏以蛊虫培养、资源获取和修行成长为核心。

蛊虫需要消耗特定食材进行喂养，但此前的喂养功能主要是占位系统，食材缺少完整且可持续的生产来源。

本次经营模块旨在补全这一环节。

玩家通过种植和未来的养殖活动生产食材，食材可用于：

- 蛊虫的日常喂养与培养。
- 完成游戏内的资源需求或任务。
- 在市场中出售，获得游戏货币。
- 参与玩家与游戏经济系统的资源流转。
- 为后续的灵植加工、配方和特殊培养机制提供扩展基础。

## 1.2 项目目标

建立一套可独立开发、测试，并能接入原有游戏的灵植经营系统。

要求：

1. 支持网格化土地管理与种植交互。
2. 支持多种作物及不同生长阶段。
3. 支持花草、灌木/茄科、树木/果树、真菌/蘑菇四类作物。
4. 提供可以持续扩充的 2D 美术资源管线。
5. 解决 AI 贴图边缘衔接、比例不一致和场景风格不统一的问题。
6. 实现播种、生长、收获、库存的基本闭环。
7. 预留蛊虫喂养、市场交易和养殖系统的接入能力。

## 1.3 开发边界

### 本轮开发

- 经营地图基础设施。
- 地面纹理和过渡系统。
- 土地状态与耕种操作。
- 作物数据模型。
- 生长与收获机制。
- 四种类别作物的视觉表现。
- 种植产物库存及对外接口。
- 基础市场与喂养数据对接。

### 暂不开发

- 动物、灵兽及蛊虫养殖。
- 复杂的天气系统。
- 完整季节生态。
- 自动化农场设备。
- 大规模 NPC 农业生产。
- 复杂农产品加工链。
- 多人实时协同经营。
- 完整农业经济平衡。

上述功能均不作为本轮验收的前置条件。

# 二、总体技术与美术方案

## 2.1 场景视角

采用正交斜俯视 2D 视角。

具体原则：

- 地面采用矩形网格，不使用等距菱形网格。
- 地表贴图以正交俯视方式设计。
- 植物、建筑、设施采用固定斜俯视角的独立 Sprite。
- 场景不采用实时 3D 摄像机。
- 大型物体通过 Sprite 排序处理遮挡。

所有作物必须遵循相同的光源方向、观察角度与视觉比例。

## 2.2 地图基础结构

地图分为以下逻辑与渲染层：

| 层级                | 内容            | 职责    |
| ----------------- | ------------- | ----- |
| Ground            | 草地、石地、泥土      | 基础环境  |
| TerrainTransition | 地形边缘、道路、水岸    | 自动拼接  |
| Farmland          | 耕地、菌床、特殊种植介质  | 可种植区域 |
| Crop              | 花草、灌木、树木、真菌   | 作物显示  |
| Object            | 树木、建筑、围栏、设施   | 环境物件  |
| Overlay           | 选中框、种植提示、交互反馈 | 用户交互  |

实际渲染顺序可根据引擎调整，但逻辑数据应保持独立。

## 2.3 地图规格

初始采用以下规格进行验证：

- 逻辑网格：32×32 单位。
- 基础 Tile 设计分辨率：64×64 像素。
- 单格植物基准画布：64×64 像素。
- 大型植物允许超出单格显示。
- 地图尺寸采用配置驱动，不固定为单一大小。
- 网格占地与素材画布尺寸分离。

这些参数为初始技术基线，Phase 0 验证后冻结正式规范。

## 2.4 美术生产方式

优先采用：

**AI 基础纹理 → 无缝化处理 → 程序生成地形过渡 → AI 独立 Sprite → 统一风格修正 → 游戏引擎导入。**

明确禁止将大量独立 AI 场景图直接作为地形网格拼接。

不同资产使用不同技术：

| 资源类型  | 生产方式                     |
| ----- | ------------------------ |
| 基础地面  | AI 无缝纹理                  |
| 地形过渡  | Mask / Autotile          |
| 作物    | AI 生成透明 Sprite           |
| 围栏及道路 | 模块化资源                    |
| 小型建筑  | AI 资产 + 结构校正             |
| 复杂建筑  | 简单 Blender 体块辅助 + AI 风格化 |

Blender 仅作为可选的结构辅助工具，不承担完整建模生产任务。

# 三、Phase 0 — 技术基线与重构准备

## 目标

在不复用旧经营底座的前提下，确定新系统的技术规范与资产标准。

### 任务 0.1：旧方案隔离

- 停止沿用此前地形生成及拼接方案。
- 将旧经营模块实现移出新模块的运行依赖。
- 将旧素材归档为参考，不作为新素材规范。
- 明确新模块与原游戏之间的数据接口边界。
- 保留仍然适用的世界观、蛊虫、道具及经济定义。

不得因为旧模块中存在某项实现，就默认新模块必须兼容它。

### 任务 0.2：项目结构设计

建议采用如下结构：

```
farming/
├── core/
│   ├── grid/
│   ├── terrain/
│   ├── planting/
│   ├── growth/
│   └── harvesting/
├── data/
│   ├── crops/
│   ├── terrains/
│   └── items/
├── rendering/
│   ├── tilemap/
│   ├── sprites/
│   └── sorting/
├── assets/
│   ├── ground/
│   ├── transitions/
│   ├── crops/
│   ├── buildings/
│   └── decorations/
└── integration/
    ├── inventory/
    ├── feeding/
    └── market/
```

这是逻辑目录示意，实际实现需要适配现有工程的技术栈（本仓库的 Godot 落位映射见附录 A.2）。

### 任务 0.3：确定美术规范

输出统一美术规范，包含：

- 观察视角。
- 光源方向。
- 色彩范围。
- 材质细节密度。
- 网格大小。
- Sprite 锚点。
- 透明区域要求。
- 输出格式。
- 命名规范。
- 图片缩放与过滤规则。

AI 生成时必须使用统一的风格约束。

### 任务 0.4：最小拼接验证

构建测试场景：

- 单一草地纹理。
- 单一泥土纹理。
- 草地与泥土过渡。
- 10×10 逻辑网格。
- 摄像机平移和缩放。
- 网格点击与高亮。

### 验收标准

- 基础地面可重复铺设，正常缩放下无明显接缝。
- 地形过渡不存在透明裂缝或错误边缘。
- 网格坐标与实际显示位置一致。
- 点击能够准确定位格子。
- 美术标准与地图坐标规范均已固定。
- 不依赖旧经营底座运行。

**阶段交付：** 可运行的空白经营地图 Demo + 技术规范文档。

# 四、Phase 1 — 地形与土地系统

## 目标

构建支持玩家种植操作的完整地图基础设施。

### 任务 1.1：地形类型

首批实现：

1. 草地。
2. 泥土地。
3. 石板地。
4. 耕地。

其中耕地为具有农业状态的逻辑地块，不应仅仅作为普通地面纹理处理。

### 任务 1.2：地形自动拼接

优先使用 47-tile Blob Autotile 或等效的 8 邻域过渡算法。

系统需要支持：

- 水平边缘。
- 垂直边缘。
- 内角。
- 外角。
- 不规则区域边界。
- 连续大面积地块。

基础纹理与边缘 Mask 分开维护。

允许初始版本先使用预定义 Mask，后续再优化为 Shader 混合。

### 任务 1.3：土地状态

至少定义：

```
UNAVAILABLE  不可种植
WILD         未开垦
TILLED       已开垦
PLANTED      已播种
OCCUPIED     已被设施或障碍占用
```

需要区分静态地形类型与动态农业状态，不建议把全部状态编码成一个地形枚举。

### 任务 1.4：土地交互

实现：

- 指向或选中地块。
- 判断土地是否可开垦。
- 将土地转换为耕地。
- 判断是否允许播种。
- 显示无法种植的提示。
- 防止多个作物占用同一逻辑空间。

### 任务 1.5：存档数据

每个地块具备稳定坐标及必要状态。

优先保存逻辑数据，而不是直接保存最终显示贴图。

地图加载时根据地块状态恢复显示。

### 验收标准

- 玩家能够在地图中开垦连续区域。
- 耕地边缘能够正确拼接。
- 多格占用不发生数据冲突。
- 土地状态保存和恢复后保持一致。
- 更新一块土地不会错误重建整张地图。

**阶段交付：** 可开垦、可交互、可存档的经营地图。

# 五、Phase 2 — 核心种植系统

## 目标

建立第一条完整种植流程。

### 任务 2.1：作物数据模型

每种作物包含：

| 字段                | 含义     |
| ----------------- | ------ |
| crop_id           | 作物唯一标识 |
| name              | 作物名称   |
| category          | 作物分类   |
| footprint         | 占地尺寸   |
| planting_medium   | 种植介质   |
| growth_stages     | 生长阶段   |
| stage_durations   | 各阶段时长  |
| harvest_type      | 收获方式（remove 单次移除 / regrow 有限次再生） |
| harvest_items     | 产出素材列表（单次收获可产出**多种素材**，每项 item_id + min/max 数量） |
| max_harvests      | 最大采收次数（regrow 型达上限后枯竭，需清理地格） |
| regrowth_duration | 再生长时间（天） |
| sprite_set        | 美术资源   |
| feed_tags         | 蛊虫食材属性 |

作物类别、种植介质、生长行为必须分离设计，避免后续新增类别时重写核心逻辑。

### 任务 2.2：作物生命周期

基础状态：

```
SEED
  ↓
SPROUT
  ↓
GROWING
  ↓
MATURE
  ↓
HARVEST
```

收获后根据作物配置进入：

- **remove 单次移除**：移除作物，恢复可种植状态。
- **regrow 有限次再生**（灌木/果树等）：保留植株进入再次结果状态；
  采收次数达 `max_harvests` 后植株**枯竭（EXHAUSTED）**，不再产出——
  需要**清理地格**后才恢复可种植状态。

### 任务 2.3：游戏时间（v1.1 固定）

时间体系常量数据驱动（`content/farming/config.json`）：

- **24 个时节 × 每时节 15 天 = 360 天/年**（时节即二十四节气，暂为纯叙事，
  季节生态效果属后续扩展）。
- **每天 24 个行动点**：耕作操作（开垦/播种/采收/清理等）消耗行动点，
  行动点耗尽或主动休息即进入次日。
- **生长周期以天为单位**：作物按「天」离散推进（day_changed 事件），
  生长逻辑独立于渲染帧率，支持跨天更新与读档恢复。
- 不因地图暂时卸载而停止必要的生长计算（生长状态入存档）。

初期不加入温度、湿度及季节限制；行动点消耗表为占位可调配置。

### 任务 2.4：播种

实现：

1. 选择种子。
2. 判断目标格子是否合法。
3. 判断种植介质是否匹配。
4. 判断占地空间是否空闲。
5. 扣除种子。
6. 创建作物实例。
7. 显示对应初始 Sprite。

种子扣除与作物创建应视为同一原子操作，避免资源丢失或重复创建。

### 任务 2.5：收获

- 检查作物成熟状态。
- 根据产出配置生成物品：单次收获可产出**多种素材**，逐项在 min–max 区间内掷数量。
- 检查库存可用空间。
- 更新作物或土地状态。
- 发送标准收获事件。

### 任务 2.6：第一批测试作物

初期只制作两种：

- 凝露草：花草类，单次收获。
- 赤纹果：灌木类，可重复结果。

名称及具体数值为开发占位配置，可由原游戏世界观配置替换。

### 验收标准

- 完成播种、等待生长、成熟、收获的完整流程。
- 两种不同收获机制正常运作。
- 生长数据可存档及恢复。
- 作物逻辑不依赖特定图片。
- 收获物可以进入库存。

**阶段交付：** 最小可玩种植闭环。

# 六、Phase 3 — AI 作物美术资产管线

## 目标

建立可重复执行的 AI 作物素材生产流程，降低后续增加作物的成本。

### 任务 3.1：统一作物 Sprite 规范

每种作物需要满足：

- 固定斜俯视角。
- 透明背景。
- 无独立环境场景。
- 统一主光照方向。
- 植株底部中心锚点。
- 合理的生长阶段高度变化。
- 同一作物各阶段保留稳定的识别特征。

作物 Sprite 不直接绘制耕地底图。

### 任务 3.2：四阶段素材

每种基础作物至少包含：

```
stage_0.png  初生
stage_1.png  幼苗
stage_2.png  生长期
stage_3.png  成熟期
```

对于可重复结果作物，可增加：

```
stage_harvested.png
```

生长阶段数量应由配置决定，不应在渲染代码中硬编码为四个。

### 任务 3.3：AI 生成工作流

推荐流程：

1. 生成作物成熟期母版。
2. 审查轮廓、视角、颜色及细节密度。
3. 以成熟期母版为视觉参考生成其他阶段。
4. 统一各阶段尺寸和底部锚点。
5. 清理背景及透明像素。
6. 检查叶片边缘、阴影及异常结构。
7. 导出符合标准的 Sprite。
8. 在真实游戏网格中预览。
9. 通过检查后进入资源库。

不依赖 AI 一次生成完美的多阶段 SpriteSheet。

### 任务 3.4：资源检查脚本

开发图片自动检查工具：

- 检查 PNG 格式。
- 检查 alpha 通道。
- 检查非透明区域边界。
- 检查画布尺寸。
- 检查文件命名。
- 检查必要阶段是否缺失。
- 检查是否超出允许的画布范围。

自动检查不能代替视觉审核。

### 任务 3.5：统一渲染

实现：

- Sprite 根据生长阶段自动切换。
- 底部中心锚点对齐。
- 跨格 Sprite 正确绘制。
- 基于地面位置执行深度排序。
- 地面接触阴影独立处理。

### 验收标准

- 能持续生成符合规范的作物素材。
- 同一种作物的四个阶段具有视觉连续性。
- 多种作物并排时比例协调。
- 透明边缘不存在明显白边或脏边。
- 资源更换不影响作物逻辑。
- 形成可供后续批量使用的标准模板。

**阶段交付：** AI 素材制作规范 + 资产校验工具 + 可用作物 Sprite 集。

# 七、Phase 4 — 四大作物分类扩展

## 目标

在不重写种植核心的前提下支持四类作物。

## 4.1 花草类（Herb）

特征：

- 通常单格种植。
- 视觉高度较低。
- 可以密集排列。
- 支持单次收获或重复采摘。

首批测试重点：

- 密集种植时的辨识度。
- 不同生长阶段的表现。
- 小尺寸 Sprite 的清晰度。

## 4.2 灌木／茄科类（Shrub）

特征：

- 通常单格种植。
- 可配置多格占地。
- 枝叶体积明显。
- 适合多次采收（次数有限，枯竭后需清理地格，见 §五 任务 2.2）。
- 收获前后可表现果实数量变化。

首批测试重点：

- 重复采收。
- 成熟与采摘后视觉切换。
- 相邻灌木的视觉遮挡。

## 4.3 树木／果树类（Tree）

特征：

- 支持 2×2、3×3 等多格占地。
- 生长周期较长。
- 具有较大树冠。
- 允许重复产出果实（次数有限，枯竭后需清理地格，见 §五 任务 2.2）。
- 视觉范围大于逻辑占地。

首批测试重点：

- 多格空间占用判定。
- 树冠跨格显示。
- 玩家与树木的遮挡关系。
- 果树采摘和再次结果。

初期不开发复杂的树木砍伐或林业系统。

## 4.4 真菌／蘑菇类（Fungus）

特征：

- 支持菌床、朽木等种植介质。
- 生长阶段可使用菌丝、幼菇、成熟菌簇等表现。
- 支持单株或成簇显示。
- 不强制依赖普通耕地。

首批测试重点：

- 专属种植介质。
- 多菌簇的视觉布局。
- 不同介质与作物之间的关系。

初期暂不加入复杂湿度和孢子扩散模拟。

### 分类扩展约束

禁止按作物类别分别创建四套种植系统。

应通过共享生命周期、配置参数与可选特殊行为实现差异化。

未来新增作物类别时，应优先采用注册或数据配置方式扩展。

### 验收标准

- 四类作物均可完成完整生命周期。
- 多格作物不会产生空间重叠错误。
- 不同种植介质能够正确限制种植。
- 不同收获类型均能正常运行。
- 新增一种普通作物不需要修改核心系统代码。

**阶段交付：** 四类作物均可运行的种植系统。

# 八、Phase 5 — 蛊虫喂养与经济联动

## 目标

在本仓库完成种植、食材喂养和元石交易闭环，对外保留主游戏经济与材料适配接口。

2026-10-09用户确认的规则与实现以 [Phase 5执行文档](phase-05-喂养与经济闭环.md) 为准：初始60元石、木属性食材、饱食度6，每日和指定成功行为各减1。当前阶段不要求实际接入上游仓库。

### 任务 5.1：道具统一

作物收获产物必须映射到原有游戏的道具体系。

建议种植模块只负责产生标准物品，不另外创建一套独立且互不兼容的背包。

若原有背包暂不适合直接复用，应通过适配层实现数据交换。

### 任务 5.2：蛊虫喂养

作物可以配置食材属性。

例如：

```json
{
  "item_id": "dew_leaf",
  "feed_tags": ["wood", "yin"],
  "source": "farming"
}
```

具体的蛊虫适配关系、喂养收益及培养效果由蛊虫系统决定。

种植模块不直接计算蛊虫属性成长。

### 任务 5.3：市场交易

收获产物支持市场出售。

第一版需要验证：

- 物品可以被出售。
- 正确扣除物品。
- 正确增加货币。
- 交易失败能够回滚。
- 商品具有可配置的基础价格。

暂不实现复杂动态供需市场。

### 任务 5.4：资源生产与消耗闭环

形成：

```
获得种子
   ↓
种植作物
   ↓
等待生长
   ↓
收获食材
   ├──→ 蛊虫喂养
   ├──→ 市场出售
   └──→ 储存备用
```

市场收益可用于购买新种子和其他生产资源。

### 验收标准

- 收获物具有标准物品ID、五行及对外材料字典适配接口。
- 食材能够被喂养系统识别和消耗。
- 商品能够通过市场出售。
- 交易及食材消耗不存在重复扣除问题。
- 种植模块无需了解蛊虫系统的内部实现。

**阶段交付：** 本仓库可运行的种植经济闭环和主游戏对接接口；上游实际接线另行实施。

### 验收标准

- 批量新增作物不需要大量重复开发。
- 能够支撑后续内容更新。

**阶段交付：** 无新增美术/音乐的Windows种植Demo，三槽自动存档、工具升级、可跳过引导、设置和首轮45天回顾。
