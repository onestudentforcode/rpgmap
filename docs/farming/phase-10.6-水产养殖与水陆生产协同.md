## 1. 讨论结论与范围

### 1.1 用户已确认

1. P10.6一起完成新物种、新设施、新蛊虫与房间，不只扩充鱼类图鉴。首批包括滤藻鲤、油鳍鱼、珍珠蚌、凝胶水母、净泥鳅、礁骨珊瑚。
2. 部分水产资源应能在具体工业配方中替代陆地原料，同时保留水产独有的特殊资源；不要求所有原料通用互换。
3. 鱼栅建在已有水面上，对标陆地地板。暂不开放陆地挖池、注水，也不模拟液体流动。
4. 鱼栅是水域铺面和边界，不绑定育幼、繁殖、生产用途；建设相应设施、划定功能区后才形成房间。
5. 水域允许混养；不同独立鱼栅水体不主动交换水质或服务。边界采用明确归属，外围表现为鱼栅，不因紧贴而自动合并。
6. 一个独立鱼栅水体共用一个充分混合的水质指标，不做逐格扩散。不同功能房间可以使用同一水体，水质共享不等于房间归属合并。
7. 水质维护需求与面积、养殖负荷有关，处理设施有容量。重划房间不能刷新水质；水体扩张、拆分、合并应继承、按面积结算原有水质。
8. 生物用途区分育幼、繁殖和生产，适当复用陆生养殖逻辑。繁殖继续采用进度制，安抚只加快繁殖进度，不另加概率判定。
9. 油鳍鱼通过捕捞取油，消耗生物，同时产出油脂和鱼肉；滤藻鲤继续为消耗生物的捕捞路线。
10. 珍珠蚌、凝胶水母、礁骨珊瑚采用不消耗生物的周期取材；净泥鳅消耗实际污泥等投料进行处理，不靠存在免费产肥。
11. 珍珠蚌取珠保留生物；取壳作为另一种消耗成体的采收选择，贝壳不随每轮取珠反复产生。
12. 专属生产设施可以建在鱼栅水面；共用供食、换水/净化配套可以建在岸边并显式关联目标水体。
13. 浮萍、芦苇、珊瑚占固定地格，挤占游动生物可用养殖面积；共享水质，但空间不能重复计算。
14. 缺食按生物单位记录，水质不足影响整个水体；先停成长、繁殖、生产并保留进度，持续若干天不满足生存条件后死亡，恢复条件中断对应失败连续计数。本期不为水产生物引入陆地劳动疲劳、罢工日程。
15. 水陆共用设施职责、蛊虫种类、用途适配与房间效果，暂不另造水产强化体系。水质由基础换水、净化设施维护，不增加专属净水蛊。
16. 共用能力为主产物增产、促进繁殖、节省基础食物。矿料、灵液、污泥等生产投料不计入口粮折扣。
17. 蛊虫按功能用途tag适配，不额外叠加陆生/水生房间白名单。同一只蛊只能入驻一个设施，卸下后可迁往另一处；共享种类不代表跨区同时服务。
18. 不同功能可以叠加；同功能不叠加，最高转生效，同转稳定选源。效果仍受真实区域、服务容量、运行资格约束，蛊虫暂不设计次要能力。
19. 本期共同补齐陆地与水产精养增产、节粮能力；陆地既有安抚、役使能力不能因此被改成第二套算法。
20. 认可三级精养基地：合格育幼区关联二级精养区；幼体按实际育幼贡献，成年进入关联精养区后取得首次生产轮初始进度，最多抵扣首轮目标的10%，每个生物只领取一次。已有繁育场继续负责子代初始成长，两类权益分别结算。

### 1.2 草案范围的补充建议

- 增加浮萍、芦苇两种水生作物；基础藻料仍由现有微藻培养槽生产，不新增浮游生物、水蚤和食物网。
- 新生物按一个UID的标准饲养单位登记；水母、珊瑚可显示为“群”，不展开群内数量，不引入卵、性别、配偶或珊瑚专属分枝生命周期。
- 保留8单位日时钟与连续2单位维持窗口；水产普通照料用剩余6单位推进。不为“与陆地共用”强行给鱼增加放牧与劳动疲劳。
- 本期强化水陆共用规则，不把所有陆生役使工艺重新定义为精养，也不为蜜蜂、净水菌毯开通没有对应功能的繁殖、精养奖励。
- 旧`fish_pond`水库路径建议从新建入口退役，由显式水体、名册与物种专属生产设施接替；是否保留独立展示入口、如何处理开发旧档在a阶段冻结。

### 1.3 不做

陆地挖池/注水、液体流动与管线、盐度/溶氧/水温/水深指标、捕食与自动食物网、动物移动寻路、卵和交配、疾病、新品质系统、实时疲劳、水产玩具、新净水蛊、蛊虫升转与饥饿死亡、市场限购、全地图生态模拟、正式美术与发行包。

旧候选池关于海水、钙质和浮游生物的描述仅供题材参考，本期用真实库存投料与单一水质指标表达，不要求实现那些环境机制。

## 3. 水面、鱼栅水体、房间与系统

### 3.1 四层关系

| 层 | 保存内容 | 职责 |
|---|---|---|
| 原始水面 | 地形、地权与水面坐标 | 决定哪里可铺鱼栅；不因铺设变成陆地 |
| 鱼栅水体 | 稳定`body_uid`、显式成员、共享水质 | 表达边界、混合水质与总承载；不指定育幼/繁殖用途 |
| 功能房间 | 稳定`zone_uid`、所属水体、显式成员、功能和设施引用 | 表达育幼、繁殖、生产等资格，同格最多一个功能房间 |
| 三级系统 | 稳定`system_uid`、房间关联和实际贡献 | 组合繁育/精养流程；不再复制地格或水质 |

同一地格可以同时是鱼栅水体成员和该水体内某房间成员，这是铺面与用途的不同层。不能同时属于两个水体，或两个功能房间。一个水体可有多个互不重叠的房间，也可以存在未划功能的鱼栅格。

### 3.2 建造与边界

- 鱼栅采用逐格1×1铺设，外沿渲染围栏，内部相邻格不画重复围栏。不是只画一圈线后自动吞入所有内部水面。
- 铺设先检查已购地权、原始水面、占地冲突；玩家明确选择创建新水体或加入现有水体。不按全图水面连通自动确定归属。
- 四邻接只验证同一水体/房间内部连通，斜角接触不连通。不同ID紧贴、隔一条内部边界，也保持独立。
- 功能区只能从指定水体内选格，不能跨水体划一个房间。三级系统可以显式关联同介质、不同水体的房间，关联不交换水质。
- 允许一个水体的不同房间共享水质；动物只使用所分配房间的空间和服务，不因为同水体就自动跨房间找食或繁殖。
- 合并/拆分必须显式预览并提交；不能用添加一格“桥”触发自动合并。编辑造成断连、切开固定占地、遗留无处安置生物时拒绝，先要求重新安置。
- 设施失效可保留合法房间ID并暂停服务；它与非法交叠、断连、跨水体的坏数据不同。

### 3.3 水质在拓扑变动中守恒

**建议内部用整数水质总量，界面只显示平均水质。**设面积为`A`、共享总量为`M`，每格水质100对应10000内部点，则显示值为`floor(M / (A × 100))`，有效范围`0…100`。

- 只改房间边界：`A`、`M`均不变。
- 合并：面积与总量分别相加，不能取两者最大值或恢复100。
- 拆分：按原统一水质、目标面积分配`M`；整数余数按稳定顺序分配，子体总量之和必须等于原值。
- 扩张：原总量加上新增水面真实继承的总量，再计算新平均值。新格不能携带比来源更高的免费水质。
- 解除鱼栅：释放地格的继承水质需留在底层来源账，重建时取回；禁止删光水体再建就恢复初始水质。来源账只负责拆建继承，不按格模拟扩散。
- 缩小：移出地格带走对应总量；不得只减少面积却保留全部总量。拆改不能切走有生物、设施或固定作物的占地来逃避安置。

首轮原始未使用水面的初始水质建议沿用100。只在该地格首次取得来源值时使用，不能每次创建`body_uid`重新发放。更换名称、ID、房间类型或读档均不是水质来源。

## 4. 承载、混养与配套设施

### 4.1 空间账

建议同时检查水体总账与房间局部账，不能拿邻居空地抵扣本房间超载。

`游动可用空间 = 房间成员格数 − 阻挡设施占地 − 固定水生作物占地 − 固定珊瑚占地`

- 游动生物按物种空间权重合计占用，所有物种混养争用同一份容量。
- 固定珊瑚先占其明确地格，不再作为游动生物扣一次同等空间；仍计入供食、照料、蛊服务及水质负荷。
- 设施/植物/珊瑚占地取并集后计数，不能靠重叠重复减扣，也不允许非法叠建。
- 休息位沿用床位可服务时段及体型容量的概念；其合法休息占地不再重复当作阻挡设施扣除。具体水面建造表现见§4.2建议。
- 房间最小空间、动物空间、供食位、休息位、生产服务量、蛊服务量是不同检查项，不能只拿一个“容量4”替代全部。
- 固定作物及珊瑚改变布局时重新预览承载；已有动物不会自动挤到别的房间。

### 4.2 共用职责与水面建造适配

用户确认的是同类设施职责和规则复用。以下为建造适配建议，不新增一套水产床、供食算法或蛊虫白名单：

| 配套 | 陆地职责 | 水面/岸边建议 |
|---|---|---|
| 圈舍/登记设施 | 归属、照料与名单入口 | 同一类登记设施允许水面构造，外观可为浮台；不是旧水库habitat |
| 供食槽 | 整段维持的食物服务 | 同类供食设施允许岸边投饵构造；显式关联一个目标水体及指定房间 |
| 床/休息处 | 维持窗口的休息容量 | 水面构造显示为栖息处，复用小/中/大和时段预约，不要求鱼躺陆地床贴图 |
| 照料台 | 繁殖或基础照料 | 同类照料设施允许水面构造，算法不变 |
| 安抚台 | 入驻安抚蛊 | 陆水同一种宿主职责，可在合格水面房间使用 |
| 专属生产设施 | 按物种承载生产与领取 | 水面建造，物种对应关系只在生产注册表维护 |
| 换水/净化配套 | 有投料、有处理容量的基础维护 | 岸边普通地板，显式关联一个水体，不因靠近而生效 |

水面构造可采用同类设施的建造介质变体；若现有地形字段只允许一个值，在a阶段先统一建造适配表达，不能复制成具有不同算法的陆版/水版。

岸边设施有自身唯一物理归属，水产房间引用它提供的服务，不再把同一实体登记进多个房间。首轮建议要求与目标水体边缘四邻接，完整占地合法；关联后不能同时覆盖另一个水体。一个供食设施可服务该水体内多个指定房间，但各时段共享同一容量，不能每个房间各领一次全额。

### 4.3 结构与个体资格分开

育幼池建议最小可用空间4；繁殖池、精养/捕捞生产池建议最小8；净泥鳅处理区建议最小4。水生种植区按种植面积检查，不要求留下同等面积供游动生物使用。

| 一级房间 | 必要配套建议 | 可运行的基础活动 |
|---|---|---|
| 育幼池 | 登记设施＋供食服务＋适配休息位 | 幼体成长 |
| 繁殖池 | 登记设施＋供食＋休息位＋照料台 | 合格成体积累繁殖进度 |
| 生产池：精养/捕捞 | 登记设施＋供食＋休息位＋至少一种专属生产设施 | 精养取材或捕捞养成轮 |
| 净泥鳅处理区 | 登记设施＋供食＋休息位＋泥料处理设施 | 实际投料处理 |
| 水生种植区 | 鱼栅成员＋合法种植格＋水生种植管理设施 | 浮萍、芦苇生长与采收 |

缺少某物种专属生产设施只暂停该物种的对应生产，不让同区其他物种断食。缺公共供食/休息配套则无法完成该区生物维持。无一级资格时设施不能生产，但生存失败计时继续。

### 4.4 固定珊瑚的安置

建议珊瑚幼群与成群均保存一个固定锚点及完整占地。购买、出生、转区先预约目标格；没有空格就不能把幼群塞进仅有抽象数量额度的育幼池。固定格本身提供该物种的栖息资格，仍需要供食、照料与生产服务。

固定不等于永远不能转用途：玩家可通过与其他生物相同的安置提交，把整个UID移到目标房间的合法空格，日界生效，表现为一次移栽。进度、已付料、贡献、凭证与生存失败计数随UID保留；不拆成多个群，不返还种苗，也不模拟移动路径。没有合法新锚点时拒绝提交，不自动拆礁或挤占植物。

## 5. 水质、维持与日结

### 5.1 建议水质参数

保留单一水质，首轮建议如下，均待a阶段冻结：

| 项目 | 建议 |
|---|---|
| 初始/上限 | 100/100，初始只发放一次 |
| 生长、繁殖、生产所需水质 | ≥30；低于30暂停，不另设隐含品质收益 |
| 每日基础下降 | 2点 |
| 负荷下降 | `ceil(6 × L / A)`点；`L`为存活饲养单位的配置负荷总和，首轮默认按空间权重；`L=0`时为0 |
| 总量变化 | 每下降1点扣`A × 100`内部水质总量，最低0 |
| 单次换水服务 | 清水2→污水2，最多按8格、每格提升40点计算；面积不足8按真实面积，投料不退款 |
| 换水AP | 每次1AP，建议同一水体每日最多一次人工换水；大水体依靠多座有容量的自动配套 |
| 自动换水 | 每设施每日一次同量服务，真实清水不足则暂停，不另叠旧habitat免费维护增益 |

例如8格水体换水最多增加`8 × 40 × 100`总量；64格水体同一服务只提高平均5点，不能同样清水2就让整个大水体提高40。超过上限部分记为处理浪费，不转存为未来清洁额度。

水质是游戏维护指标，不是水的体积。换水只按实际配方产出污水，不根据面积、鱼数再生成一份污水或底泥库存。暂不增加独立“沉积物浓度”状态。

### 5.2 日时钟与维持

建议复用8单位时钟，默认`M,M,C,C,C,C,C,C`。水产成体在繁殖、生产/处理用途间互斥，幼体只成长。供食与休息必须在同一个连续维持窗口内齐全，不允许只吃或只休息取得完整资格。

- 育幼每成功维持窗口1份基础餐，繁殖与生产每窗口2份，沿用陆地对应口径；每份见§6。不能把“每份食谱”误当成每天总量。
- 水质合格、房间成立、足够食物、休息位和空间均满足，才提交维持成功；扣餐与服务收据同一事务。
- 维持失败后本日不推进水产成长、繁殖或生产，补食后也不回补已经错过的照料单位；下次完整维持窗口成功再恢复。
- 水产不积累劳动疲劳，不套陆地每日`+12`维持失败疲劳、罢工或额外放牧公式。陆地的固定8单位禁工与疲劳规则原样保留。
- 专属生产补料不足、生产位已满只暂停生产，不把它计为断食或劣水。蛊缺费只失去强化，基础资格齐全仍正常运行。
- 切换用途、区域、休息预约沿用日界生效，保留已有轮次和已付款；不靠切换用途重做当天维持。

### 5.3 死亡建议

分别记录每个饲养单位的连续维持失败天数、连续劣水天数。首轮建议任一达到3个实际结算日则死亡；成功维持清零前者，经历合格水质日清零后者。按真实日结更新，不按打开面板、换房间或重载次数计数。

缺食、缺休息位、公共空间/结构失效导致维持失败，不能靠保留空食槽逃避生存计时。死亡只核销一次，不自动产鱼肉、贝壳或珊瑚石；个体精养权益随之核销，设施已有处理批次则按设施批次契约保留。

日结建议统一顺序：提交既有预约/用途→扣蛊维护并决议可用来源→自动换水→维持与照料服务→成长/生产/繁殖/处理完成→日末水质负荷→失败连续计数与死亡→写账和存档。

建议本日服务的水质资格统一取自动换水后的共享水质，覆盖本日8单位，并记录采样值；泥鳅完成带来的改善正常写入总量，用于下一日资格，不倒补本日单位。日末下降同样影响下一日，避免动物遍历顺序造成同日不同生存判定，也不追溯推翻已合法完成的服务。

手动操作、自动维护、最后AP与保存失败在候选世界中提交；失败回滚包括清水、污水、水质总量、随机、进度、死亡、服务费用及账本，重试不能多扣或多产。

### 6.3 珍珠蚌取壳

建议成年、合格生产池、有兼容采珠台时可以选择取壳，1AP批量操作，单只产贝壳2并移除该生物。没有额外取珠奖励；不对取壳开放精养轮增产、首次精养进度奖励。

- 已有待收珍珠时先领珍珠，取壳入口不把待收权益再转成第二份珠。
- 正在生产的轮次，操作预览明确核销进度与已付投料，不退款；不默认替玩家领取。
- 同一UID的取壳、捕捞、出售/移除、死亡互斥，成功移除后不能再领繁殖、精养或首轮权益。
- 不从幼体取壳，不增加蚌肉、珍珠粉等没有本期用途的副产物。

### 6.4 净泥鳅处理

净泥鳅处理属于外部投料工艺，进度归设施岗位/批次，不能同时再记一份个体精养进度。借用既有开批、付料、待领、换班继续批次的契约；物种本期没有陆地劳动疲劳，不因此开启放牧/玩具/协同役使余量。

建议每处理台4个岗位，一个饲养单位同一时段最多服务一个岗位；实际获岗、原料齐全、基础维持及水质合格才推进。缺料不产生工作量，也不增加新的生存惩罚。

建议完成一个真实批次时，对所关联水体增加至多“8格各8点”的水质总量，按实际面积与上限截断；完成事件只执行一次，领取腐殖土时不再净化。投入污泥是库存实物，不能从水质下降额外生成同一份污泥，也不能未付料就改善水质。

净泥鳅不是普通换水的替代开关：既能消耗已有净水菌毯/工业产生的污泥，也需要供食、空间和设施。是否长期抵消某规模水体负荷，必须用真实处理速率比较。

### 6.5 统一生产权益

精养与捕捞养成轮沿用个体轮次：开始时锁定UID、轮次、配方/补料变体、目标、投入、基础产出；第一份实际进度与扣料同一事务，之后缺供暂停。完成后待领封顶，不自动开下一轮。

捕捞领取同时提交产物与生物移除，不能先产油再保留同一条鱼。普通精养领取只清结本轮，生物继续存在。转区、换兼容设施、切换繁殖用途、存读档都保留轮次与已付款，不重开或退款。

增产资格与随机结果在生产完成事务锁定；待领后装蛊、移动到高级房间或反复开预览均不重算。处理型批次的实际库存投入与产出另走设施批次账，不混入个体首次精养奖励。

| 珊瑚复合石板 `assemble_coral_panel` | 木工台 | 珊瑚石2＋石粉1＋黏液1→复合石板3 | 真实使用陆地蜗牛产物 |
| 保水基质 `make_water_retaining_matrix` | 农产加工台 | 凝水胶1＋腐殖土1＋苇秆1→保水基质4 | 水产独有加工资源，实际供水生种植使用 |
| 珍珠精滤 `pearl_polish_water` | 净水菌毯 | 污水6＋过滤介质1＋珍珠1→清水4＋污泥2 | 新的高投入净水工艺，不直接提升邻近水体水质 |

a阶段核实旧培养作物如何表达可选投料，为木腐菌绑定开轮锁定的变体，不另外注册一种同义蘑菇或一台“菌料工厂”。普通加工仍绑定现有设施注册表；若P10.5最终基线调整了承载或投料路径，记录对应变化，不默加一整条新工业。

**油脂路线：** 油鳍鱼取油直接产出既有`crude_oil`，随后使用原`refine_oil`。不额外生成一份油饼，也不把附带鱼肉同时当作已消耗的原料；两项产物来自捕捞轮的一次结算。

**矿料回路：** 珊瑚石2制石粉2，而一轮珊瑚消耗石粉3，基础转换有损；腐殖土、鱼粉、复合饲料循环也要计入真实生物口粮、损耗和AP。不得靠新旧配方组合在无外部投入下无限增发矿料或食物。

### 8.3 灵液高级生产变体

建议不新增品质状态，采用开轮时可选的配方变体：

| 变体 | 投入建议 | 目标 | 基础产出建议 |
|---|---|---|---|
| 灵液育珠 | 石粉1＋灵液1 | 24照料单位 | 珍珠3，替代普通珍珠2 |
| 灵液凝胶 | 清水1＋灵液1 | 12照料单位 | 凝水胶3，替代普通凝水胶2 |

两变体均为可选强化投料，不能把露壳蜗牛灵液变成所有水产的必需口粮。变体开轮锁定，不能快完成时补一滴灵液追溯改产出；未付该变体投入就不能领取高产量。

### 8.4 获取、研究与价格建议

- 基础入口建议开放鱼栅、共用育幼/维持配套、滤藻鲤及捕鲤台、浮萍和芦苇；藻料来源沿用当前基础配方。
- 油鳍鱼和取油台建议复用农产初加工门槛。珍珠蚌、水母及基础专属台建议复用水循环研究；净泥鳅和处理台复用生物过滤；珊瑚和采礁台复用矿质建材。
- 建议增加一个高级水产研究节点，暂名`aquatic_intensive_care`，前置水循环，样本珍珠2＋凝水胶2，费用10元石、4日，解锁灵液两变体、保水基质与珍珠精滤。基础珍珠/凝胶必须先可产出，灵液必须已能从陆地获得。
- 鱼粉和复合饲料变体复用现有高级饲料研究；贝壳/珊瑚制粉、多孔滤材与建材绑定对应加工研究。每项只用当前研究系统可表达的门槛，不增加新研究表达式语言。
- 新增原料建议不可直接购买，保留出售与合适供货出口：珍珠卖6、凝水胶卖4、贝壳卖1、珊瑚石卖2、浮萍/苇秆各卖1、鱼粉卖2、保水基质卖2；种苗卖0。供货资格在a阶段逐项冻结。
- “买价0”表示不可买，不是标准成本0。新幼体仍可不限购，不在本期暗中补市场约束；繁殖不能仅靠提高买价证明划算。

上述配方不会自动证明经济成立。尤其灵液当前出售价值较高，应比较投入灵液与直接出售的机会成本；调整变体增量、周期或价格必须有专项账。

## 9. 水陆共用蛊虫与二级房间

### 9.1 三种能力

| 蛊虫 | 建议用途/效果键 | 宿主 | 首轮效果 | 维护/来源建议 |
|---|---|---|---|---|
| 既有安抚蛊 `soothe_gu` | 保留`animal_breeding_assist` / `breed_speed` | 安抚台 | 保留繁殖进度150% | 沿用现有1元石/日与已有获取路径 |
| 丰养蛊 `product_yield_gu`，暂名 | `animal_product_assist` / `product_yield` | 合格物种专属精养/捕捞设施 | 主产物期望＋25%，不加快生产 | 一转，1元石/日，无新增蛊食；建议市场32元石/只 |
| 节粮蛊 `feed_saving_gu`，暂名、食道 | `animal_feeding_assist` / `feed_saving` | 共用供食槽 | 基础食物消耗−25% | 一转，1元石/日，无新增蛊食；建议市场32元石/只 |

新增蛊的名称、tag字符串、倍率、购买价与维护均是建议，已有安抚效果保持现行值。新蛊不按陆/水分别发定义，不重复发放无限试用包；每个实例每日维护一次，不按服务动物数收费。

新增丰养蛊首批覆盖陆地四种精养、滤藻鲤/油鳍鱼捕捞、蚌/水母/珊瑚精养。净泥鳅外部处理批次、既有陆生役使配方、贝壳消耗采收暂不纳入精养增产，避免把提高矿物处理产量作为本期附带改动；它们仍可使用适用的繁殖、基础节粮服务。

生产设施建议新增一个单槽，供食槽新增一个单槽。安抚台维持原槽。同一房间可由不同宿主提供繁殖/增产/节粮能力，但单个生物同一时段只能执行当前用途；不同功能可共存不代表繁殖与产物进度同时增长。

### 9.2 适配只维护一处

- 宿主槽定义接受的用途，生物/工艺定义自己提供的能力；以这两项决议兼容，不在房间再列一份“羊/鱼/蚌可用”的名单。
- 去除旧`terrestrial_animal`对共用安抚目标的硬限制，改用繁殖能力等功能判断；不能只改UI可装而保留结算器的陆地过滤。
- `medium`约束用于地形建造和生物安置，不作为蛊种的第二套白名单。不会繁殖的叶丝蚕仍不能因安抚蛊通用而繁殖。
- 同实例唯一入驻；转移必须先撤回，再在另一个合法宿主部署。部署、撤回、最后AP、读档都保持实例总数守恒。
- 宿主服务对象来自显式房间/关联，不加跨区光环。初版按每宿主每时间单位4空间服务，混养按同一份容量排序分配。
- 同功能对单次事件只选一个来源，先最高转，再同转稳定UID；最高转容量已满后，其他来源只能服务尚未获该功能的对象，不能继续叠加在同一对象上。
- 供食槽自身的基础餐位与蛊服务容量分别检查；蛊有空位不能把已满的食槽变成可供食。

### 9.3 增产按真实生产贡献结算

沿用用户认可的“整数部分＋小数概率”思路，但不能只在收获瞬间检查蛊是否在场。建议记录每轮真实受强化的生产点。

设本轮基础主产物数量为`n`；扣除合法首轮初始进度后，实际需要的生产点为`R`；每次真正填入目标的生产点为`b_i`，该次实际增产百分比为`p_i`，未获服务为0。则：

`期望额外数量 = n × Σ(b_i × p_i) / (100 × R)`

取整数部分必得；剩余分子以同分母的整数随机比较决定额外1份。全轮得到25%服务时，退化为`n × 0.25`；只覆盖一半实际生产时为`n × 0.125`。

- 虚拟初始进度不冒充蛊服务，`R`在开轮锁定；所有实际生产得到强化时仍享受完整25%，不因合法首轮奖励反而少拿比例。
- 只登记主产物：钢绒、蚕丝、灵液、矿鳞、鱼肉、粗油、珍珠、凝水胶、珊瑚石。羊粪、鱼粪、黏液、蜕皮、油鳍鱼附带鱼肉不增产。
- 最后一次进度只计实际填入目标的点，溢出不制造贡献。多个设施不能为同一生产点分别记账。
- 在完成事务做一次随机并保存奖励；待领、换区、欠费、拆台不会重新掷骰，也不撤回已合法锁定的产物。
- 随机采用独立用途序列/事件身份，不污染农业首次种子、玩具等已有随机；读档重试不得换结果，预览不得推进随机。

### 9.4 节粮使用整数累计抵扣

小额口粮不能逐餐对`1 × 0.75`向下取整。建议按“生物UID＋食物资源ID”保存不足一份的节约累计量：

`x = 本餐基础数量 × 节约百分比 + 原余数`

`本餐节约 = floor(x / 100)`，`新余数 = x mod 100`，`实际扣除 = 基础数量 − 本餐节约`。

一份食物、25%节约、初始余数0时，四次实际扣除为`1、1、1、0`，合计3份。零扣除来自先前有效服务的累计折抵，不代表没有食槽、休息位或蛊维护也能进食。

- 先在候选状态计算本餐应扣量，再同时验证基础服务、有效来源和库存；全部成功才扣餐、提交余数与维持收据。失败不能空刷余数。
- 余数属于生物和资源，不属于可反复换装的蛊；换区/换槽/同类蛊不会重置或赠送新抵扣。未得到有效节粮服务时按原餐正常付费，余数封存，不拿来免一顿普通餐。
- 食谱换为另一资源时使用该资源自己的余数，不把桑叶折扣兑换成油饼；余数均需有历史有效服务来源。
- 只减少食谱中标记为基础食物的资源。陆地随餐饮水、鱼栅换水、蛊自身维护食料、矿质补料、灵液、污泥、生产开轮桑叶均不享折扣。
- 不用节粮改变连续维持时长、休息预约、空间需求或陆地禁工处罚；基础条件失败照常失败。

### 9.5 配置等级与实际效果

一级结构合格可正常运行；安装适配蛊形成二级配置。缺元石/蛊食时显示“二级配置，强化暂停”，普通设施恢复基础效果，不把动物的食槽也停掉。结构不合格则基础服务暂停，不能只靠仍有蛊支付就继续工作。

精养区可以有增产宿主和节粮配套；二者是二级能力共存，不因为装了两种蛊就自动升三级。三级必须满足§10的跨房间组合与实际服务条件。

## 10. 三级繁育与精养基地

### 10.1 沿用已有繁育场

合格繁殖区获得安抚服务，并关联合格目标育幼区，按P10.4真实繁殖贡献给对应子代最多10%初始成长。陆地仍检查原疲劳、维持和预备容量；水产检查对应水质、维持和空间资格，不增加虚构疲劳。

同一个水体内也必须是两个明确房间，不因同水质就免去目标育幼配套。跨水体关联不转移水、不统一水质；出生安置需目标本身合格。叶丝蚕、蜜蜂、净水菌毯等原本无该繁殖能力的对象不自动纳入。

### 10.2 新增三级精养基地

**确认组合：** 合格育幼区＋关联二级精养区。建议二级目标必须有实际可运行的丰养蛊生产服务，不能仅装不适用的安抚蛊便宣称满足精养强化；节粮配套可选，不是本组合必备。

建议按介质兼容及物种生产能力建立目标引用；陆地幼体只能去可安置的陆地精养区，水产幼体只能去可安置的水面生产区。蛊共用不意味着鱼能转入羊圈。

**作用：** 幼体实际获得合格育幼服务后，成年首次进入目标精养生产轮时，获最多目标10%的初始进度。捕捞养成轮复用个体生产契约，可以纳入；净泥鳅的设施处理批次不纳入，不得靠连续换泥鳅给同一批次反复赠进度。

### 10.3 不监控整段人生，只记实际事件

建议为幼体显式指定同系统目标精养区。每次实际成长时检查：育幼区一级成立、该次维持/照料有效、目标区二级配置和所需共用能力当时可用、具有适配该物种的生产设施，以及目标承载预备额度可分配。成立才记录该目标的成长贡献`E`。

- `E`只计真正填入成长目标的实际成长点；P10.4出生赠送的初始成长、手工夹具成熟、读档恢复、成年后驻留均不是育幼贡献。
- 目标预备额度共用同一承载账，不能对无限幼体同时声明同一份空位；不从此预约获得即时生产量。
- 改目标只影响未来事件，旧贡献不能复制给新目标。首轮建议采用明确改目标并放弃原目标贡献的操作，留核销收据；不做隐式追溯迁移。
- 房间临时失效只停止之后积累，不清零已经取得的合法贡献。房间删除、目标解绑或主动放弃按明确核销操作处理。
- 成年后转去普通区、暂时工作或等待可封存未用权益，不在这些用途兑现；必须回到关联、兼容、当前合格的目标精养区才能首次使用。

设成长目标为`G`、累计合格实际贡献为`E`、第一次生产轮目标为`T`，建议初始进度为：

`C = floor(T × 10 × min(E, G) / (100 × G))`

因此普通完整育幼最多获得`T × 10%`；只覆盖一半成长过程最多5%。若子代已有繁育场赠送的初始成长，那部分不再计为实际育幼，不能用赠送进度继续无成本制造第二笔贡献。

### 10.4 首轮使用与防重领

1. 每个生物UID只有一张首次生产凭证，不因换区、改名、换设施、切用途、换补料或读档重置。
2. 开始首轮生产前先检查普通生产资格，并完整支付本轮原料；然后在同一事务锁定配方目标、消耗凭证并加入`C`。奖励不减少矿料、灵液等投入，也不能只凭奖励完成整轮。
3. 初始进度保存在该生物的这一轮；中途停产不再发第二次，换兼容设施继续，不退款或转成物品。
4. 没有符合条件的育幼贡献就普通开轮；一旦已开始首次生产，之后才补建育幼/精养系统不能追补奖励。
5. 变体的目标和基础产出在该轮开轮锁定，不靠换高价变体重算信用。捕捞/取壳/死亡核销该UID未使用的权益。
6. 缺费或结构失效可封存尚未使用的合法权益；只有恢复合格目标才能兑现。已合法加入本轮的进度不因之后降级倒扣。

### 10.5 多配置并存

繁育场、精养基地、既有协同役使场都属于三级不同配置，不升四级。一个管理系统可包含多种配置，分别按对应生物、用途、房间与事件结算，不给“综合基地”再叠全局倍率。

首轮建议物理房间归属一个管理系统；同系统的育幼区可被繁育和精养流程引用，但成长、预备容量、UID及凭证共享同一账。系统拆合不重发出生奖励、首次生产凭证或工作余量。

## 12. 玩家操作、信息与表现

### 12.1 操作流程

1. 在已有可用水面铺鱼栅，明确创建或扩张目标水体；预览面积、总水质变化和围栏外沿。
2. 从水体成员中划育幼、繁殖、生产/处理或种植房间，配置共用配套与岸边服务关联。
3. 购买幼体/幼群并预约空间、休息位或固定格；选择食谱及成年用途，真实推进成长。
4. 在兼容宿主部署现有安抚蛊或新共用蛊；查看实际可服务数量、费用与未获服务的原因。
5. 创建三级管理系统并关联育幼、繁殖、精养目标；预览贡献只从以后真实事件积累，不立即发满奖励。
6. 经专属设施领取产物；捕捞明确展示同时移除名单，珍珠蚌另提供取壳操作及在制权益损失说明。

建议沿用既有建造/拆除、部署/撤回、安置提交、批量领取AP口径：普通建造与领取1AP，显式系统关联提交1AP，划区/命名免费。鱼栅批量铺设需显示总AP和材料，a阶段绑定既有批建规则，不把逐格1AP静默改成任意面积1AP。

### 12.2 必须可解释的信息

- 水体：ID、面积、水质、总负荷、今日下降、已用处理量、维护投料及各房间分布。
- 房间：一级结构缺件、安装后二级配置、当前强化是否生效、三级关联缺口；区分公共空间与逐物种设施不足。
- 生物：登记单位、用途、当前食谱、维持资格、连续失败、成长/繁殖/生产进度、已付补料、预计主副产物及待收。
- 蛊：实例所在宿主、功能、最高转选源、服务容量、当前费用、欠费暂停，不把未分配对象显示为已增强。
- 精养基地：目标、实际育幼贡献、预备额度、预计首轮信用、凭证未用/已用/核销状态。预览数值不等于已经获得奖励。
- 取壳/捕捞：即将移除的UID、待收/在制处理、实际产物；批量操作先展示完整结果再作为普通生产操作提交，不新增额外审批流。

### 12.3 表现与知识交付

实施需要可辨认的鱼栅外沿/内部水面、功能房间边界、固定作物/珊瑚锚点、六种生物图标、专属台、共用水面构造及新增资源图标。沿用当前投影、占地与选中规范，水面贴图不能遮掉相邻房间的内部边界。

可以先用可区分占位资产验证玩法；占位图不登记为正式美术验收。百科/手册在实施阶段从内容源补齐物种、来源/消费者、配方、蛊用途、共享水质与三级流程；本次草案不导出、不改已有生成文档。过去某阶段的UI自动化豁免不自动适用于本期，代理也不代签玩家主观试玩。

## 15. 验收设计与分区补跑

### 15.1 模型与契约

首先运行秒级模型/配置专项，覆盖实际不变量，不以大量复述实现的断言代替场景证明：

- 水面地权、显式归属、四邻接、相邻独立、同水体跨房间共享、跨水体无交换、固定占地与复合容量。
- 水质总量合并/拆分/缩放守恒，来源继承、整数余数、不因删建变新水；维护只改目标水体、真实耗料/产污水与容量。
- 连续维持、成功扣餐、缺食/劣水分别计时、恢复中断连续失败、死亡唯一核销；水产没有虚构疲劳，陆地既有禁工/疲劳不变。
- 一生物一用途、成长/繁殖/生产互斥，个体权益与设施处理批次分离；付料一次、完成一次、领取一次、移除互斥。
- 油鳍鱼真实移除后给粗油和副产物；珍珠蚌两采收选择；珊瑚固定锚点/实际矿料；净泥鳅有输入才处理，完成净化只执行一次。
- 同种蛊可从陆地撤回装水产，错用途拒绝、最高转/稳定选源、共享4空间、同实例不重复维护，不保留目标陆地硬编码。
- 增产全程/半程/临近完成才装蛊、主副产物区分、小数确定性、无效服务不计贡献，完成后切换不重抽。
- 节粮1份四餐累计、混合资源/餐份、换食谱、缺费封存、失败零变更，不误减饮水/灵液/矿料/蛊维护。
- 三级目标预备容量、全程/部分/末尾育幼、虚拟初始成长不贡献、实际首轮付款、切区/换台/换配方不重领。
- Codec正常/暂停状态往返、非法引用/负数/交叠/超发拒绝，预览只读，最后AP和实际保存失败完整回滚。

概率测试用固定种子或可注入的确定性序列检查成功、失败及边界；不能要求有限次随机恰好等于25%。如需统计平衡分析，单独报告样本与误差，不混作脆弱的日常门禁。

### 15.2 模块场景，单条不超过30日

| 分区建议 | 真实流程与主要断言 |
|---|---|
| `water-boundary` | 铺鱼栅→创建两个紧贴水体→同水体划不同房间→换水→扩张/合并/拆分/解除重建，质量与归属可审计 |
| `survival-capacity` | 混养、固定作物/珊瑚挤占、供食/休息位争用、缺食与劣水分别恢复/致死，不重复死亡 |

| `loach-coral` | 现有净水工艺真实产污泥→泥鳅批次→腐殖土施用；矿料→珊瑚取材→滤材/石粉，净化与产物各只一次 |

### 15.3 独立账本与篡改探针

逐日向外部证据保存完整起终库存/元石、操作与日结收据，不只保留游戏末15日历史。审计器从起始夹具和事件重建，不调用被测效果函数生成“期望值”。

收据至少含：水体拓扑与水质总量变化、换水实物、水质负荷、维持食谱/份数/实际扣除、服务来源与共享容量、UID购买/出生/转区/移除、生产开轮/批次投料/进度/主副产物、增产贡献与随机、节粮余数前后、三级成长贡献/预备与首轮凭证、死亡核销。

篡改探针至少拒绝：

1. 删建鱼栅刷新水质、合并多发总量、伪造跨水体维护。
2. 同一地格/固定锚点/服务额度重复使用，超容量仍领取完整服务。
3. 同一鱼捕捞两次、捕捞后继续繁殖，蚌取壳后再领珍珠。
4. 清空已付款重新投料/退款、无原料处理、泥鳅完成与领取各净化一次。
5. 主副产物都增产、临近采收追溯满轮贡献、改已锁定的随机结果。
6. 节粮失败刷余数、换槽复制抵扣、把基础食物折扣用于矿料/灵液。
7. 伪造幼体实际贡献、复用目标预备容量、首轮凭证二次消费、免付首轮原料。
8. 同蛊双宿主、维护只付一次却跨两区全额服务、原库存/现金篡改、缩短失败连续计数。

审计器本身需用诚实账本和人工篡改账本验证，不能只证明一个Codec入口会拒绝。所有失败探针保留预期拒绝原因，区分“工具崩溃”与“正确识别违规”。

### 15.5 经济对照与长线整合

成本报告分开列一次建设、鱼栅/地权面积、休息/供食/生产位、蛊购入与维护、基础餐、生产投料、AP、处理损耗、真实有效时间、主副产物价值、停工与死亡风险。不可购买物使用可追溯标准成本，不把测试夹具现金或免费库存当利润。

至少比较：
