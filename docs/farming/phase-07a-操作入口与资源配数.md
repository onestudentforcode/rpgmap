## 1. 手动/委托操作入口设计

### 1.1 现状与问题

当前底部"农务工具"栏选工具后**只能框选创建雇工待办**；手动操作藏在地格侧栏下方的图标行（成功 1AP）。玩家无法从工具栏看出"立即执行"和"交给谁做"的区别（Phase 7 §3 指出的问题）。

### 1.2 工具栏目标布局

```
收起时（常驻一行）：
[农具展开] [手动｜委托]切换  当前模式说明文字

展开·手动模式：                       展开·委托模式（=现行布局）：
 查看 开垦 播种 收获 浇水              查看 开垦 播种 收获 浇水
 施肥 砍伐 清理      （8项）          施肥 砍伐 清理 取消 区域（10项）
                                     优先级 [1-9 SpinBox]
说明文字：
 手动 · 点选目标立即执行 · 成功扣1AP
 委托 · 框选创建待办 · 雇工日结执行 · 成功才收费 · 不耗玩家AP
```

- 模式切换是常驻的分段按钮（小图标＋文字），当前模式**任何时候可见**；图标尺寸不变，执行方式与成本只用文字说明。
- 手动模式隐藏"取消标记/负责区域"（它们是委托概念）与优先级框；委托模式与 V1 完全一致，不改变现有框选、优先级、区域逻辑。
- 悬停预览（沿用 hover_hint 行）：手动模式显示"开垦 · 成功扣1AP"或失败原因（如"不可开垦：石板地"）；委托模式保持现行提示。

### 1.3 手动模式行为

- 选择动作后**点击单个目标立即执行**（首批单目标，不做拖动批量）；调用与侧栏完全相同的 world 模型函数（`till/plant/harvest/irrigate/fertilize/fell/clear`），同一套校验、AP 扣减、日志与统计。
- 成功：扣 1AP（`standard_action_ap`），notice 提示结果；失败：零改动，提示具体原因。
- 采收成熟作物不弹确认；清理仍弹确认（与侧栏现行规则一致）。
- 手动"播种"沿用该格选种计划（与侧栏手动播种同源）。
- 手动失败不创建任务、不扣料、不过日；只读预览不产生任何副作用。
- V0 高级 3×3 工具（M 页购买、整批 AP 折半）不因手动模式自动出现；"手动批量工具是否进 V2"仍为 Phase 7 §3 的独立待确认项。

### 1.4 侧栏与设施/资源点面板

- 地格侧栏：把"手动操作"图标行**上移到格名/状态行正下方**，完整种植资料保持在下方滚动区。
- 资源点面板：现行"手动采集（1AP）"按钮与"指派雇工"分区显示的结构保留，作为圈舍/水场面板的模板。
- 圈舍/水场面板（P7.b 实现，本批定结构）：上部为三栏配置（动物/基础食物/特殊食物）＋状态与进度；下部固定两区——**手动操作**（基础投喂/特殊投喂/剪毛·出塘/水体维护，各显示 AP 与所需材料）与**指派雇工**（按设施 UID，同资源点模式）。
- 连续工具、右键查看、Esc 层级、模态输入阻断、存档失败保护全部保留。

### 1.5 防重复规则（手动与雇工共享）

同一行为最终调用同一模型校验：手动与雇工不能重复采同一株、收同一批、重复投喂同一日（按个体级 `fed_day`/`cycle_fed_day` 标记判定，见 §5.3）；委托只新增待办不立即扣工资；手动失败零改动。

| 水体可用度 | 0–100，建场即100；有在养个体 −5/日；**≤30 暂停**该场全部成长与周期（不清进度）；出塘不受暂停限制 |

### 4.3 手动操作 AP 与工作量汇总

| 操作 | 方式 | AP | 成功条件 |
|---|---|---|---|
| 基础投喂 | 手动1次/设施·日；或雇工 | 1 | 有在养个体、库存够"全部适用个体×食谱"；仅投未喂个体 |
| 特殊投喂 | 手动1次/设施·次；或雇工 | 1 | 存在空闲成体、特殊料充足；按空闲成体数扣料 |
| 剪毛/出塘 | 手动1次/设施·次；或雇工 | 1 | 存在待收个体 |
| 水体维护 | 手动或雇工 | 1 | 水场有在养个体且可用度未满 |
| 购入幼体 / 配置食谱 / 切换食谱 | 面板 | 0 | 只改配置与个体记录，不扣料不推进时间 |

零在养投喂、满进度重复点击均不构成成功工作，不扣 AP/工资、不重复产出（Phase 7 §4.3）。

### 4.4 雇工新工作类别（P7.d 实施，本批登记口径）

在现有 8 类偏好上新增 3 类（0–5 偏好、日预算、成功上限沿用）：**养殖投喂**（一次巡栏完成基础＋特殊两类有效投喂）、**养殖收取**（剪毛/出塘）、**水体维护**。设施按 UID 独立指派（同资源点模式，不受农务负责区域限制）；同一设施多格占地只生成一份任务；建造拆除仍手动。

## 5. 地图与水库（20×22）

### 5.1 布局

- 新地图 `farm_02`：`size [20,22]`；y=0..13 与 `farm_01` 完全一致（陆地、泥地、石板、资源点位置 y=8、光照区域不变）；y=14..21 共 8 行全为水域 `w`。
- `terrains.json` 新增 `water` 地形：`tillable:false`，先以纯色占位图接入；岸线过渡与水面美术归后续美术批次（同 Phase 7"先用可辨识示意图"口径）。
- 环境数组（水分/肥力）覆盖全图 440 格，水域格不参与种植与消耗，仅为索引完整。
- 快照中 `map_id` 为 `farm_02`；V1 `farm_01` 与全部 V1 校验不受影响（water 只是 tillable_map 里的一个新键，V1 不引用）。

### 5.2 建造校验拆分

把"可开垦"与"可建某类设施"分开：陆地设施（圈舍/藻槽及全部 V1 设施）要求四格为可开垦地形；水场要求四格全为 `water`。水域 `tillable:false`，**不可通过把水域标为可耕来绕过**；禁止越界、跨岸、覆盖植物/资源点/其他设施。

### 5.3 相机与快照

- 全图适配按 20×22 重算（fit-all 缩放变小约 20–25%），P7.f 在主规格与三种兼容窗口、三档 UI 缩放下重新截图验收可读性；若试玩判定字图过小，备选方案是纵向滚动视口——该备选**不默认实施**，只作为登记的回退项。
- 坐标/环境/耕地/作物/设施校验全部按新尺寸；框选、边界、地图数据同步调整。

## 6. 存档方案

| 项 | 方案 |
|---|---|
| 产品标识 | `farm_demo_v2`（V1 `farm_demo_v1` 不动） |
| Schema | 7（V1 现行 6 之后顺延；只新建，不做 1–6 迁移） |
| 存档目录 | `user://farm_demo_v2_slots`，三槽、每日自动保存、失败阻断＋原样重试、覆盖确认沿用 |
| 入口 | `play.bat v2` 开发期独立入口；默认 `play.bat`/F5 仍为 V1，切换默认入口待 P7.f 确认 |
| 旧档 | V2 入口打开 V1 档明确提示"不支持的档案，请重新开档"，不静默解释、不自动覆盖 |

`world` 新增字段（在 V1 world 字段之上）：

```
pens: [ { uid, facility_id(pen|fish_pond), origin,
          species_id,                    # 每设施单物种
          basic_recipe, special_recipe,  # 三栏配置（食谱ID，可持久更换）
          individuals: [ { uid, stage(juvenile|adult),
                           growth,                     # 0..growth_days*100
                           cycle_state(idle|running|ready),
                           cycle,                      # 0..cycle_days*100
                           fed_day, cycle_fed_day } ], # 个体级当日服务标记，防同日重复投喂
          water } ]                       # 仅水场：可用度0..100
next_pen_uid, next_animal_uid
```

- 占地沿用同一 Grid 原子占用（2×2 reserve）；`environment` 尺寸 440。
- 日结顺序扩展为：**雇工（含投喂/维护/收取）→ 养殖结算（水体衰减→暂停判定→成长/周期推进→待收标记）** → 作物与环境 → 资源点刷新 → 加工完成 → 订单推进 → 日报/回顾 → 自动保存。每个面板不得自行推进一天。
- 当日新购幼体、刚转成体的个体按个体级服务标记判定首次生效日：未获当日服务的个体当日不成长；刚成体当日无特殊投喂不产出（Phase 7 §4.6）。
- 日志/回顾新增条目类型：幼体购入、投喂、水体维护、暂停原因、剪毛、出塘、副产物；45 天回顾增列养殖投入与期末幼体/成体数，不把生物和材料估值冒充现金利润。

## 7. 经济接入与供养值

### 7.1 订单

订单生成机制不变（五行路径、rank1–5、静态供养值）；新食材凭 `supply_allowed＋element` 自动进入对应供货池：金订单可收**钢绒**（与铁锭并列），木订单可收**鱼肉**（与谷粒/木腐菇并列）。报价公式不变：数量=⌈需求/供养值⌉、回款=数量×售价×110%。rank 门槛与 V1 售价不动（Phase 7 §5）。

### 7.2 成本模型与供养值预估

新增 4 个成本模型（bake_v2 成本审计输出最终值）：

| 模型 | 投入 | 产出（分摊） | 预估供养值/售价 |
|---|---|---|---|
| grass | 草籽1＋清水1＋AP4 | 牧草3 | 不供货（内部成本 ≈2.0/份） |
| algae | 清水3＋秸秆2＋AP2 | 藻料6 | 不供货（≈0.6/份） |
| wool | 牧草3＋清水3＋含铁矿石1＋AP2 | 钢绒1(0.9)＋羊粪肥1(0.1) | **钢绒≈10 / 卖12** |
| fish | 藻料6＋谷粒1＋AP3＋cash5(鱼苗) | 鱼肉3(0.85)＋鱼粪1(0.15) | **鱼肉≈4 / 卖6** |

- 幼体购入与设施造价为一次性发展支出，**不摊入**产物标准成本（Phase 7 §5 口径）。
- 成本图无环：wool→grass→采购种子；fish→algae→秸秆堆肥链/泉水/麦；腐殖土基准仍是秸秆堆肥，"喂养→粪肥→饲料"循环不参与定价。
- 幼体仅采购；食物/补料采购按物品配置（§2）；采购→出售/供货全程防套利（§7.3）。

### 7.3 防套利检查（bake_v2 固化）

- 钢绒全采购路线：牧草2×3＋清水2×3＋矿石4＝16 ＋AP成本 ＞ 卖12/供养10 → 亏损 ✓。
- 藻料不开放采购 → 鱼肉无法全采购复制 ✓。
- 幼体不可出售；出塘/剪毛一次结算，无重复回款 ✓。
- 粪肥不可采购（买0），堆肥增值属回流收益、受周期产能上限约束 ✓。
