## 1. 目标与玩家问题

梳理当前可玩版本的完整玩法，制作可以在游戏内查阅、按类别浏览、按名称搜索、沿生产与用途关系跳转的百科全书，并导出同源的完整游戏手册。

百科应让玩家回答：

- **这是什么？** 属于哪一类，有哪些属性、环境要求与使用限制？
- **怎样获得？** 从哪里采、种什么、养什么、在哪个设施加工，投入和产出各是多少？
- **可以做什么？** 哪些配方、饲养、建造、研究、维护或交易会使用它？
- **还缺什么条件？** 需要什么科技、前置科技、设施、种子或幼体，等待多久，消耗多少行动和元石？
- **为什么没有按预期生产？** 缺水、缺肥、光照、照料、花源、水体、待收取和有效工作日分别怎样影响生产？

例如，金穗麦条目要能查到光照偏好、每天水分与肥力扣减、生长与采收规则、谷粒/秸秆及数量；秸秆条目要列出全部获取途径与直接用途，并能继续查到每条用途的科技、设施和完整配方。不限于这两个示例。

## 2. 范围与现状

### 2.1 本期覆盖

以**当前默认P8的实际运行内容**为全集，覆盖初始内容、研究锁定内容及其继承实现。V0/V1/V2独立入口的历史玩法和未来候选库不混入现行条目。

### 2.3 边界

- 本阶段整理并展示现行规则，不改配方、价格、成长速度、经营平衡或P8.7投影。
- 调查发现实现与设计不符、没有用途或可疑数值时，登记证据与问题，不通过百科内容擅自修正玩法。
- 不新增动物模型、工作特效、繁殖/寿命、音乐或上游蛊虫玩法。已实现的供货接口与本地供货规则须说明，不能写成完整上游养蛊已接通。
- 静态百科内容不要求提升schema17。浏览历史等会话状态与经营存档分离；收藏、持久阅读进度、多语言及大型全图生产网络不作为首版完成条件。

## 3. 条目规范

### 3.1 通用字段

每个实体有稳定的`类型:原始ID`、玩家名称、分类/标签、简述、相关图片或图标、解锁条件、关联条目、数据依据。名称以当前UI/注册数据为准，不能用文件名或资产名代替。

百科展示静态规则；当前持有量、已研究/未研究、当前设施等动态信息可叠加显示，并明确“本档状态”。无存档时仍可阅读完整静态内容。未研究条目默认可见，标注锁定原因，阅读不解锁玩法。

### 3.2 按类型的必备数据

| 类型 | 必备字段 |
|---|---|
| 作物 | 种子/菌种及每次种植投入、占地/介质、解锁、光照目标/适宜范围与偏离效果、水分/肥力阈值与每天扣减、首次成长与再生周期、花期、成熟/再生/砍伐/清理行为、每种产物及数量、授粉等条件增益 |
| 物品/材料 | 属性与标签、全部直接来源、全部直接用途、相关工艺投入产出与数量、购买/出售/供货资格及价格规则、关联科技和设施；无来源/无用途必须解释或登记缺口 |
| 建筑/设施 | 建造材料和元石/AP、占地与地形限制、科技、功能/容量/覆盖范围、支持物种/配方/食谱、运行维护消耗、操作与负责人规则、拆除及返还规则 |
| 养殖/培养物种 | 幼体/培养单位价格与解锁、适配设施与容量、成长周期、基础食谱及每日消耗、特殊食谱及周期投入、有效生产条件、产出及计量单位、收取后保留/移除、缺料与水体/花源影响 |
| 配方/食谱 | 执行主体、完整投入/产出及共产品、单批/单单位/整场口径、批时/有效生产日、启动与收取AP、科技/前置设施/物种条件、扣料与入库时点、暂停恢复、自动执行限制 |
| 研究/科技 | 前置研究、一次性样本和费用、研究台、有效研究日与每日推进条件、手动/雇工成本、解锁的物品采购/作物/设施/配方/物种/食谱 |
| 资源点 | 位置/定位、每次产出、每日上限及其计量口径、AP、刷新时机、雇工规则；不把地图中的实例重复当成新资源种类 |
| 规则页 | 光照/水肥/水体/花源、AP/日结/入库、雇工额度/预算/优先级、目标库存/保留量、市场/供货、土地与存档；链接到受规则影响的实体 |

不存在的字段显示“不适用”，无法确认的字段记录“待核实＋原因”，禁止用0、空字符串或估算值冒充已知事实。完成版关键玩法字段不能留无说明的待核实项。

### 3.3 数值与条件口径

1. **环境值与库存物品分开。** “每天扣4点水分”不等于每天耗4份清水；每次浇水的投入及恢复值另列。多格作物要说明扣每格还是扣整株，成熟待收期间是否仍扣也须核对。
2. **光照给出数值及效果。** “喜光/喜阴”是解释标签，须附目标、容差和偏离时的实际效率；不能把效率下降写成完全不能种植。
3. **时间说明成立条件。** 标称成熟天数标为适宜条件下的首次成长天数；首次/再生、自然日/有效研究日/有效生产日分开，说明日结推进与暂停。
4. **数量保留计量基准。** 每株、每占地格、每只/群/培养单位、每场与每批分别标注。养殖的参考满容量成本不能当作单只消耗。
5. **扣料与领料分开。** 启动扣料、日常照料、周期开始投料、开日耗料、完成待收与实际入仓分别写；在制或待收产物不能作为已持有材料。
6. **条件增益不并入基础产量。** 花源共享、授粉奖励、特殊食谱、研究/设施门槛独立列出；互斥路线和一次性奖励不得累加为日均产量。
7. **派生数值说明公式。** 成本分摊、供货取整与报价来自运行时烘焙结果及实际公式，不把设计成本模型当作真正的生产路径。

## 4. 生产侧与消费侧

### 4.1 统一关系模型

以“**实体—过程—实体**”保存事实。一个过程描述谁执行、消耗什么、在什么条件下产出什么，以及科技、设施、时间、AP/元石和扣领时点。多投入、多产物共用一条过程记录；物品页的来源与用途由同一记录正反向生成。

过程至少区分：采购/初始赠予、播种与采收/砍伐、资源点采集、普通加工、日常照料、活体生产、手采花源、换水回流、建造、研究投样、浇水/施肥、装置维护、出售/供货。没有物品产出的消耗过程仍须登记。

- **消耗**：数量实际扣除的物品、元石或AP。
- **条件**：持有设施、已完成科技、物种成长状态、光照、水体、花源或有效工作等；不因为需要设施就把整座设施列成每批耗材。
- **解锁**：科技开放的采购、种植、配方、物种等，单独关联。
- **状态变化**：水分恢复、光照提升、研究进度等效果；不伪造成入库物品。

基础食谱、特殊食谱和`recipes[].living`可能指向同一活体工艺。先确定实际执行路径，登记规范过程ID及原始映射，避免重复计算来源/消费。不同物种内的同名食谱必须带物种与食谱类型限定。

### 4.2 玩家阅读方式

材料页先显示一跳的“获取来源 / 直接用途”。每行列出数量、执行设施/物种、科技和时间，点击打开相关过程或条目；下一级再沿材料继续查。研究投样、建造、照料、装置燃料、出售等不能只藏在配方列表之外。

生产链预览只作有限层展开，并检测循环、去重、保留共产品和条件。回流链允许有环，不能强制将整个产业网络排成树；研究前置则应保持实际DAG。间接用途标为“下游用途”，不得混进直接消耗计数。

### 4.3 两个贯穿验收样例

- **金穗麦 → 秸秆**：从作物目录进入，核对种植与光照/水肥、首次成长、收获的各产物；点击秸秆可见对应数量及该来源。再查秸秆每一项用途及其设施/科技，返回时保留目录、搜索与滚动位置。
- **精炼油、清水等跨系统材料**：覆盖普通加工以外的装置耗料、照料、换水、净化和交易出口；证实反向索引来自全部过程，而非仅扫描配方输入输出。

这些是重点样例，不替代全部实体的覆盖验收。

## 5. 调查交接与数据维护

### 5.1 事实来源

按实际加载链核对：源配置 → bake派生结果 → P8数据加载器 → P8运行实现及其V2/V1继承路径 → UI可达入口。`content/farming/p8/production.json`是主要源表，实际加载的是`content/farming/baked/p8/production.json`；仅看源表会漏派生值，仅看P8文件会漏继承规则。

重点路径：

- 配数与编译：`content/farming/p8/`、`content/farming/baked/p8/`、`tools/farming/bake_p8.py`及其导入的公共bake逻辑。
- 玩法：`scripts/farming/p8/p8_{data,world,operations,workforce,research,flowers,devices,husbandry,land}.gd`，以及V2/V1实际调用的世界/养殖/交易/工作/订单模块。
- 入口与说明：`scenes/farming/farm_p8.tscn`、`p87_scene.gd`→`p8_scene.gd`→V2/V1场景继承、现有手册与对应测试。
- 地图与环境：实际加载的地图、地形及扩地配置，不能直接套用历史地图的可建设范围。

旧设计文档用于理解背景和发现差异，不覆盖实际运行事实；冲突要列出双方证据。

### 5.2 调查交付物

调查智能体仅在`docs/farming/encyclopedia/audit/`下输出，完整任务见[调查提示词](phase-09-实体生产与消费调查提示词.md)：

| 文件 | 内容 |
|---|---|
| `catalog.json` | 带版本/来源的实体、过程、规则与原始ID映射；作为后续编译输入候选，尚不直接接入游戏 |
| `report.md` | 按类别的总目录与逐条事实，至少完整展示金穗麦和秸秆两类样例，并覆盖全部实体 |
| `coverage.json` | 实际枚举数、逐ID/逐必备字段覆盖、双向关系与引用检查、排除项及理由、待核实数 |
| `issues.md` | 配置/实现/旧文档冲突、疑似断链、无来源/无用途、命名与计量问题、优先级及证据 |
| `audit_entities.py` | 只读枚举和一致性复核入口，记录运行命令；不修改玩法或重新烘焙 |

每项核心字段和过程关系附可定位的证据：相对路径＋JSON Pointer，或路径＋函数/行号；同时记录调查提交号、脏工作区状态、关键输入SHA256及调查日期。区分静态核对、实际运行验证和未验证推断。

### 5.3 正式内容来源

调查交付不等于百科内容自动验收通过。P9.b复核后再确定正式结构：静态字段从现行注册表/烘焙数据生成，运行公式和人工说明只维护一份可追溯的规则描述；不要把调查快照中的所有数值复制成另一套长期手工数据。

百科目录、双向索引和离线手册由同一正式内容层生成。增加实体或改变配方时必须触发覆盖、引用和内容过期检查，避免游戏已改但百科未改。格式版本与经营存档schema分开编号。

## 6. 游戏内界面约定（拟采用）

- 沿用当前手册入口；阅读区提供分类总目录、名称/ID/标签搜索、条目详情与返回。中文名称为主，ID仅作为辅助检索，不占主要阅读空间。
- 宽窗口可并列目录和详情；小窗口顺序切换，保持返回路径。长配方/长用途列表换行和滚动，避免横向挤出数据。
- 作物先展示生长条件与产出，材料先展示来源与用途；再展开详细规则。数字带单位，科技和设施可点击。
- 从种植详情、物品/仓库、市集、营建、设施配方、研究页提供相应条目的查询入口。优先做到“看到某物就能查”，不必先退回总目录。
- 全文可查，未解锁内容标出门槛；不以发现/收集系统遮蔽本轮手册数据。无存档也能进入，存档状态仅影响动态标记。
- 查询、搜索、翻页和返回不推进时间、不扣AP、不扣钱、不投料。百科页本身不承担购买/建造/研究启动操作；如提供前往经营页面的链接，仍遵循原有交互与确认流程。
- 阅读窗口与输入框获取焦点时，经营快捷键不穿透。日结或动态刷新保持当前条目、搜索条件、历史和合理的滚动位置。
- 复用现有模型缩略图/图标，缺图时用类型图标与文字降级，不因缺图漏条目。首版不要求新美术资产。
