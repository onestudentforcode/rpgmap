## 1. 目标和边界

V1通过种植、天然资源点、加工、销售与供货形成经营循环。五行各有至少一条生产路线，原料具有竞争用途；玩家在直接销售、加工、生产回流和订单交付之间分配资源。首次45天回顾，无强制胜负或缺货惩罚。

| 范围 | V1决定 |
|---|---|
| 首批植物 | 金穗麦、速生杉、松脂树、木腐菇四种；名单来自候选库，不扩大到18种 |
| 天然资源点 | 采石点、采矿点、泉水点；储量无限、每日产能有限 |
| 首批加工 | 木材加工、枝条炭化、有机废料堆肥、矿石冶炼 |
| 五行 | 材料属性和食材资格分离；不采用相生相克 |
| 操作 | 俯视点击、没有人物；沿用24AP/天、15天/节气 |
| 地图 | 沿用当前20×14规格，设施占地，不扩容；具体位置在布局批次验证 |
| 仓储 | 全农场共享计数库存；液体、气体和储热材料同样按物品数记录 |
| 环境 | 新增水分、肥力；固定区域光照；低水低肥降低效率，不致死 |
| 自动化 | 已启动加工按天自行完成；付费自动播种/采收/采矿放V1后半 |
| 交易 | 元石、固定价格；基础种子及生产投入可购，成品主要自产出售 |
| 外部需求 | 独立订单面板，接收流派/rank/需求量，交付后扣库存并支付溢价 |
| 存档 | 保留三槽和日自动保存，V1与V0目录隔离，不迁移旧档 |
| 验收 | 五行供货、加工回流、收入再投资，45天连续经营及状态恢复 |

养殖、水产属于产品V2；油籽花随榨油扩展加入，草腐菇作为后续候选。榨油、集热、人工资源点与资源点升级后置。复杂物流、容量、腐败、品质、天气、真实昼夜和热量模拟不属于V1。

蛊虫本体、饱食度、战斗、成长不在本仓库继续实现。V0测试蛊虫仅保留在历史开发测试中。未来特殊单位接口也不能成为普通经营的强制依赖。

## 3. 资源定义与静态供养值

资源可以有多个用途标签；初级/中间/精制描述生产阶段，不限制销售或后续加工。五行使用`wood/gold/water/fire/earth`，UI显示木/金/水/火/土。V1每种资源先定一个主要五行，接口输出对应单元素`path_ids`集合，为后续复合归属留空间。

核心配置：唯一ID、名称、属性、形态、阶段、用途标签、来源、消费者、买卖价格、食材资格、标准单位成本及供养值。`sources`/`consumers`应从生产与消费关系核对，不能靠手工重复列表逐渐漂移。

“具有五行属性”不代表“可供养”。例如原矿可用于冶炼，普通岩石可用于建设，但首批不默认作为食材。首批可供养清单见资源表。

### 标准成本与分摊

```text
批次标准成本 C = 固定元石支出
                + Σ(投入数量 × 投入材料标准单位成本)
                + 标准AP × AP权重
                + 标准天数 × 时间权重

产物j标准单位成本 = C × 分摊权重j / 标准产量j
所有产物的分摊权重合计 = 1
```

种子采购和加工投入只能在公式中计一次；不能同时把种子购买价记为现金支出又重复计作材料成本。基础采集按标准产量分摊采集AP；生长周期按标准条件计算，实际缺水、雇工或升级不改材料价值。

各食材供养值以分摊后的标准成本折算为正整数，沿用向上取整的简单口径；权重和转换比例属于数值配置。非食材供养值为0。多来源产物（如腐殖土、原木）选定一条基准来源，其他来源不会改写同一物品的供养值。

供养值最终写入配置，为静态换算表，不在每次采收或交付时按实际历史重算。数值检查需报告分摊前后总成本及取整差额，避免各副产物重复承载整批成本。

标准成本依赖必须可按顺序计算：可选施肥增产不作为基础种植的强制成本输入；腐殖土选定基础堆肥配方作为基准，不以“施肥→增产→再堆肥”反馈循环递归重算价值。基准成本图和实际资源回流图分开，允许资源回流，禁止成本定义互相依赖而无法求值。

## 4. 种植与环境

- 金穗麦：收获谷粒和秸秆，采收后重种。
- 速生杉：破坏性砍伐收获原木和枝条，砍后重种。
- 松脂树：成熟后长期周期采脂；玩家也可砍伐取材，砍后重种。同一操作只执行一种采集方式，不能先砍伐又重复采脂。
- 木腐菇：每轮消耗培养料，收获菌菇和腐殖土；重新生产需再次投入培养料。菌床是土地使用状态，培养料是每轮消耗物，二者不能混为永久可用的一份材料。

水分、肥力随游戏日变化；浇水消耗库存清水，施肥消耗腐殖土。普通条件能够生产，改善条件提高效率；不要求每次缺水都停止所有经营。真菌及各植物偏好、消耗速度、生长效率的分段系数在数值表定义。

有效光照来自固定区域配置，UI提示适合的种植用途。真菌可偏好阴区，不引入动态阴影计算。首版土地水分/肥力按格保存，多格植物的取值与扣除必须采用一致聚合规则，避免占地越大意外得到多次增益。

## 5. 资源点、设施与加工结算

天然资源点具有固定位置、产物、每次采集量、日容量和当日已用容量；手动成功采集消耗AP，无效或额度不足不扣资源。人工与手动共享同一资源点日容量。

日容量只随游戏日推进刷新，不随打开面板、重载、主菜单往返或现实时间刷新。放弃当天时，当日采集量、库存与AP一起回退。

加工设施与作物共用土地占用校验，禁止重叠。已占用地格、已有作物和资源点不能被建设覆盖；拆除、在制批次和退款政策在设施批次落地时明确，不允许以重复拆建返还已消耗原料。

已确认：启动扣原料，完成生成产物，启动和收取消耗少量AP，加工按游戏天推进，无需逐日点击，燃料作为投入物。

首版实现建议：每座设施一个在制批次；完成产物保存在待收记录，领取后转入共享库存，未领取不自动启动下一批。它是领取状态，不构成额外仓储容量限制。流程为`空闲→加工中→待收→空闲`，具体数量和天数配置化。

生产入口在任何扣款前检查完整投入、AP和状态；失败零改动。记录确定的批次ID、配方、投入、开始日、完成日与输出，不在读档后重新抽取产量。完成与领取均不可重复；末AP触发过日时保存完整结算状态。

每日增长、环境、资源点额度、加工完成、订单刷新及雇工结算采用稳定顺序后自动存档，不保存一半日结算。日顺序由实施批次统一定义并覆盖同日联动测试。

## 6. 五行订单与rank

### 已确认的规则

- 独立于蛊虫与商队的配置模板订单；每日数量有限，每单仅结算一次，未完成不罚款。
- 流派与材料属性匹配，且材料有食材资格；首版每单一种食材，自动计算必要数量，不混合、不分批提交。
- rank范围为1～5，需求量先线性增长，验证1/3/5；rank随经营进度开放，测试入口可指定档位。
- 材料供养值不随rank改变。对供养值`v`、需求量`D`，交付数量`q=ceil(D/v)`；一个完整物品带来的剩余供养值不额外生成奖励或库存。
- 订单支付相对必要交付材料市价10%的溢价；采购材料也可交付，采购价必须高于含溢价回款。

### 配置与实现建议

`D(rank)=D(1)×rank`。基准需求量、日订单数及rank解锁门槛待45天经营策略校准；rank1初始开放，解锁使用累计经营进度，不因购买设备导致余额下降而降级。

对必要数量`q`和当前固定售价`p`，市价`B=q×p`，整数回款建议`R=B+floor(B×10/100)`。UI显示实际整数溢价，低金额不保证每单至少奖励1元石。提交前同时显示数量、供养值、市价和回款。

每种可采购食材须满足任意合法订单数量下`q×buy_price>R`；可用更强的单位价约束`buy_price>1.1×sell_price`静态检查。检查只禁止同种物品直接买入再供货套利，不禁止付出加工成本后获得正常经营利润。

订单需有唯一ID、生成日、流派、rank、需求量、完成状态、实际交付及回款记录；全部随槽保存。领取成功同时扣库存、记完成、加元石、记收入，不能存在只发钱未标完成的中间状态。失败或重复提交零改动。

首版建议未完成订单在次日刷新，不扣款；已完成订单不在当天补发。回到菜单或读档不能刷新订单；如放弃当天，则订单、奖励和材料一同回到当日存档状态。日结束时的新订单在下一天才可操作。

商队联动只留档：未来可把订单来源接到商队到访叙事。本阶段不设计商队时序、驻留或交易细节，也不把历史调查参数当成当前生产限制。

用户提供的上游线索为`trade_rules`第4行动到访、驻留3行动、3资源换1元石，仅记录为后续查找依据；本轮未重新核验上游源码，不接入V1订单时序或价格。

## 7. 付费人力与经济消耗

V1后半加入自动播种、采收、采矿。配置工作范围、任务、当日预算/工作量上限；只对真实成功次数支付元石，无人物实体。无钱、无种、无目标或额度不足停工，失败不收费。

基础AP和生长时间仍用于静态供养值；雇工费用属于实际经营支出，不改变材料营养。成功工作只结算一次，不能在重载时重复扣款或产出；采矿仍受资源点日总容量约束。

建设/设备购买消耗元石及材料，构成发展端；施肥、培养料、燃料构成生产回流端；出售和订单构成收入端。设施造价、初始种子和启动资源尚待配数，需验证初始60元石能够进入经营而非卡在购买第一座必要设施。

首次45天回顾保留种植、收获、产量和经济统计，新增加工、采集、五行交付与订单收入、建设和人工支出。净收入必须覆盖所有实际支出；初始物资不记收入。移除V1的本地蛊虫喂养指标，用交付指标承接供养材料消费。

### V1.b执行记录

- `scripts/farming/v1/v1_world.gd`提供独立生产模型，复用`LandGrid`、`FarmClock`、`FarmInventory`，不依赖V0作物或测试蛊虫。操作接口为`plant/till/harvest/irrigate/fertilize/collect`；`harvest(cell, "fell")`选择树木砍伐，松脂树默认采脂。麦/杉采后释放全部占地回耕地；松脂树首次8天，采脂后进入3天再生周期，砍伐移除植株且不同时给松脂。
- 木腐菇每轮播种消耗菌种1、木屑3、清水2，采后释放耕地而不返还培养料；培养用水同时补菌床水分，不再要求额外浇水或另扣AP。未完成加工/市场接入前，测试通过明确的夹具投入验证菌菇，并未给正式新游戏赠送免费木屑。
- 水分/肥力按格保存，初值60，范围0～100；空地不衰减，有植株的每格在日结扣配置的水肥消耗，成熟待收植株同样维持环境消耗。生长先取当天环境再扣消耗，产量固定，环境只影响到成熟所需时间。
- 阳区光照80，`[0,9,8,5]`阴区光照30，地图维持20×14。多格植物按占地格水分、肥力和光照平均值计算一次生长，随后逐格扣消耗。理想一天积累100进度；水分/肥力阈值30，低水50%、低肥75%、光照偏好差超过20时50%，效率相乘向下取整且至少增长1；不死亡。浇水/施肥各1AP，消耗清水/腐殖土1份，单格增加30并封顶100；满值、不合法地格、投入不足均不扣资源。
- 三资源点按固定坐标查询，采集使用共用的物品单位日配额；超限失败零改动。配额只在`World.end_day()`或末AP触发日结时刷新，读档和放弃当天恢复快照内实际额度。
- 快照升级为V1 schema 2，新增`world`：地图ID、耕地坐标、全图水肥、作物UID/占地原点/进度/状态/采收次数、下一UID、资源点日期及额度。占用从作物定义与原点重建，不另存易冲突的第二份占用数据。`v1_world_state.gd`先在独立数据中校验完整性、越界、重复/重叠、成熟一致性和配额，再恢复世界；不合法读档不改现有状态。仅V1.a schema 1基础快照补空世界；仍拒绝导入或转换V0存档。
- 完整操作先扣投入、更新占地/产物/配额，再消费AP；末AP过日依次生长、扣环境、刷新配额，最后保存全量快照。`start_new/open_game/abandon_day`对应独立三槽；日保存失败保留上一份磁盘快照并暂停后续操作，`retry_day_save`只重试待保存快照，不重复日结，非待保存状态不能手动存档。
- 验证：31项QC、42项Python工具（新增环境完整性/固定光照边界检查）、234项V0农场、77项V1基础、152项V1生产检查通过；Godot导入通过。生产检查含四生命周期、每轮培养料、条件降效/恢复、多格均值、日容量、JSON往返、损坏快照拒绝、末AP五种操作、弃日回退、三槽隔离、写入失败重试/回退；日志`.art-work/v1-b-regression.log`。

### V1.c执行记录

- `World.build_facility(cell, id)`建设四种设施：全部占地通过校验后才扣元石、材料和1AP，设施与作物共用`LandGrid`，不覆盖资源点、道路、作物或其他设施。`facility_at`从任意占地格返回独立副本；设施下原有耕地随快照保存，恢复/拆除时保留逐格原状态。
- `World.start_batch(facility_uid, recipe_id)`实现九条配方变体：锯切、两粉碎、炭化、三堆肥、两冶炼。先验证设施适用性、空闲、完整投入及AP，再一次扣原料/燃料。每设施只有一个批次；启动1AP，锯切/粉碎1天、其余2天。产物保存在待收批次而不是直接入库存，设施自完成且不自动启动下一批。
- 批次字段为全局唯一`batch_id`、配方ID、整数投入/产物、开始日、完成日及`processing/ready`状态。固定产量在启动时记录，日结只将到期批次置`ready`，多次过日或重载不会重复生成库存。`claim_batch(facility_uid, expected_batch_id)`只接受当前待收批次；扣1AP、增加记录产物、清空批次后才触发末AP日结。强制核对批次ID，旧请求不能领取同设施的新批次。
- 首版拆除政策已落地：`demolish_facility(uid)`仅允许空闲设施，1AP，无元石/材料退款；在制和待收批次不能拆，不支持中途取消。拆后土地恢复建设前的开垦状态，防止拆建刷原料或吞掉未收产物。AP和零退款政策在`config.construction`集中配置与检查。
- 快照为schema 3，新增设施记录、下一设施UID和下一批次UID。严格校验占地重叠/越界、批次全局ID、设施配方对应、记录投入/产量、开始/完成日及状态一致性；JSON解码数值统一成整数。V1.a基础与V1.b种植快照分别补空新增字段，保留原有作物、水肥和资源点额度；仍不读取或转换V0存档。
- 日结顺序现在是作物生长→逐格环境消耗→资源点刷新→加工到期→一次完整存档；末AP建设/投料/收取/拆除都先完成操作再日结。读档与弃日恢复设施、批次、货币、库存及占地；保存失败沿用暂停、重试与弃日回退，重试不重复投料或加工完成。
- 无注入材料的生产回流测试：从初始60元石和种子，自种两杉/麦、采集石矿/清水，建四设施（共46元石，余14），锯切造冶炼炉、粉碎木屑培育菌菇、枝条炭化后冶炼、秸秆堆肥后施肥。最终真实库存谷粒3、菌菇3、木炭2、腐殖土2、清水8、铁锭1，木屑余2、矿石余1；五行自产已通，但订单交付尚未实现。
- 验证：31项QC、43项Python工具、234项V0检查、77项V1基础、152项V1生产、269项加工检查通过；Godot导入通过。覆盖全部九配方、共享投入/燃料、建拆原子性、忙碌/待收批次保护、重复/过期领取、在制/待收读档、旧V1快照升级、同日联动与失败保存重试；日志`.art-work/v1-c-regression.log`。
