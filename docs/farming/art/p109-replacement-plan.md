# P10.9 非建筑美术替换实施计划

日期：2026-10-22。依据当前代码、源图记录与用户最新要求制定。当前代码基线为`d1931f7`；此前源图归档提交为`1458194`。

## 目标与执行路线

把已制作的生物、植物源图变成默认P8.7场景实际使用的运行素材，先完成可回退的游戏内试装，再逐物种切换。建筑/设施继续沿用既定后续建模安排。

本计划建议先用现有非建筑PNG制作2D运行版验证同屏效果。专业图生3D保留为某项机位/结构确实无法匹配时的修复路线；不把所有PNG先转模设为接入前置，也不把一次二维缩放称为精确相机重投影。严重机位问题单项记录、再按既定图生3D路线处理。

## 2. 接入规则

- **源图、运行派生图分开。** `assets/farming/p109/source/`继续保留`.gdignore`和原始像素；运行输出计划放在`assets/farming/p109/runtime/`，以清单引用。每张记录源SHA256、输出SHA256、画布变换、根点和显示尺寸。
- **抠图与修图。** 钢绵羊黑底通过定向背景提取生成派生图，抠图/内容修整使用内置生图工具，保留已选形体；不通过删黑色像素破坏深色蹄和角。普通运行导出只做必要的尺寸、画布和格式整理，记录可复现变换。
- **按物种统一画布和根点。** 根点按四足接触中心、植物根冠或水中参考点人工标注；alpha包围盒只用于留白检查，不代替根点。幼体和幼苗在相同画布中保留真实年龄体量，不把每阶段各自放大到同样包围盒。
- **先匹配现有显示契约。** 植物优先匹配旧manifest的显示尺寸与占地，再用样板检查调整。源图尺寸不是世界尺寸；动物的空间权重也不是精灵宽度。运行分辨率按实际显示和最大常用缩放选择，避免直接全量加载千像素源图。
- **非像素设置。** 沿用Linear和mipmap，保持连续alpha与无损导入；以深浅底和实际草地/水面检查边缘。不会套用像素素材的Nearest、二值alpha和整数缩放要求。
- **运行状态用叠层。** 正常adult/juvenile或植物阶段图与饥饿、疲劳、待领取、选择状态分开。生命状态和生产信息读取当前系统，不依赖图中装饰猜测。水色、接触影和投影各处理一次。
- **回退粒度是物种。** 保留legacy和p109视觉配置及原运行资源；完整物种阶段组通过后才切默认。缺失幼体或阶段时显式诊断并使用可辨占位，不能悄悄用成体冒充幼体。

## 4. 动物通道的实施设计

建议增加`p109_living_visuals.gd`和运行manifest，通过一套`visual(species_id, stage)`读取34张素材，再由两个适配器取实际个体：

1. `world.ranch.state.animals`：9陆生＋6水产。读取当前生效的stage、zone_uid、bed_uid/slot、anchor，以及实际工作/照料记录；`pending`只用于预览，不能提前改变当前显示阶段或所属区域。
2. `world.husbandry`的habitat/individuals：蜜盏蜂与净水菌毯。由所属设施定位，每个培养单位的图像和计数语义一致；避免同时从两个系统重复绘制。

固定物种复用现有anchor。其余个体按当前所在区域、床位/岗位和uid分配稳定展示槽位；无岗位时从可展示单元中确定性选位，避开不适合叠放的设施。切换区域、成长、出售/死亡、读档或设施变更后重建视图缓存。展示位置不写回动物状态，不引入游走AI或新存档字段。

把生物主体送入`p87_scene.collect_entities()`现有根点排序，沿用Y、X、类型、UID的稳定次序，接触影、水色与主体分层。新增种类同时补齐`contact_visual()`、`cast_visual()`的分派，不能让animal落入source阴影分支。鼠标仍通过现有地格投影与区域/设施操作命中；完整地图交互检查后再考虑额外的个体点击能力。

## 5. 样板验收和验证范围

**画面：** 在默认P8.7真实GPU绘制中保留相同镜头的前后截图，至少覆盖疏排、密排、旧设施同屏、水岸四类。窗口1920×1080与2560×1440，检查常用远近缩放。重点核对成年羊抠图、幼成体比例、树冠遮挡、植物阶段根点、水下个体与岸边关系、面板遮挡下的地图识别。

**语义：** 验证植物阶段/花期/再生选择，幼体成长后切adult，购买/领取/出售/死亡/换区/读档后的刷新；蜂与菌毯的数据归属。显示数量与逻辑名册一致，待执行调度不提前显示为已生效。

**交互：** 放置预览、选择框、地格命中、摄像机边界、区块绘制和水房间仍与当前投影一致；不能只验独立HTML图片。

**稳定性：** 运行清单的路径/哈希/画布/根点有效，无重复导入和每帧解码；测量旧版与新版同场景的纹理内存、载入耗时、密集个体帧时间。保留原玩法数据和schema26。代码变化后运行受影响的投影/场景/成长切换与保存读取检查，纯视觉替换不默认重跑90/120日经济路线。

**切换条件：** 文件检查通过、相关逻辑验证通过、实际同屏视觉审阅有结论后，逐物种启用p109完整阶段组。任一关键接触/机位问题未解决，保留该物种旧默认或显式占位，其他已通过物种可继续。
