# Phase 5 — 喂养与经济闭环

依据：[上游调查](phase-05-上游接口调查.md)。本阶段在本仓库实现，对上游提供字典数据适配接口，不迁移 SQLite 或上游 host 单体。

## 已确认规则（2026-10-09）

- 钱包字段 `primeval_stones`，单位元石，初始 60，非负整数。
- 四种作物及收获材料均属木：作物/蛊 `path_id=wood`，材料 `path_ids=[wood]`。五行值 wood/fire/earth/gold/water。旧 feed_tags 只作风味标签。
- 测试蛊初始/上限饱食度 6；每经过一天减 1。指定行为成功后也减 1，通过接收行为名称和成功状态的方法触发，首批允许 battle。失败或普通种植操作不扣使用饱食度。
- 仅归零可喂，喂后恢复 6；归零禁止使用，本阶段无死亡、成长或战斗实现。
- 交易、喂养不耗行动点，无每日限次。
- 菌床材料、朽木作为商品；准备对应介质消耗一份，介质可重复种植；普通耕地只消耗行动点。
- 钱包、库存、测试蛊和喂养记录随农场一起保存；旧存档补默认值，不变更已有库存。

## 成本折算（首版配置，可调）

综合成本 = 种子买价 + 消耗品买价 + 行动点总数 × 行动点权重 + 生长总天数 × 时间权重。

两项权重初值均为 1。按完整生命周期计：开垦占地格数、一次播种、全部采收、再生作物一次清理；非土壤介质计准备动作和一份材料。生长天数包含后续再生。预期产量使用收获数量上下限的平均值乘采收次数，只计食材，不抵扣随机返种。复用介质/地块仍按标准新建成本估值，避免食材价值随存档状态变化。

每份食材营养值 = max(1, ceil(综合成本 / 预期食材总产量))。

为保持简单，一餐所需份数 = ceil(6 / 每份营养值)，一次校验并扣除后恢复至 6，不引入部分投喂。超过一餐需求的营养不结转。该折算是本模块平衡规则，非上游既有规则。

种子买价首版取原 base_price，收获材料卖价沿用 base_price；收获材料不在市场购买，种子与生产材料暂不回售。菌床材料买价 6、朽木买价 4，均配置管理，无动态行情。

## 分批交付

1. 文档：调查与规则、范围、验收。
2. 核心：商品配置、五行与估值、交易和指定行为使用接口、库存数量护栏。
3. 接入：市场/库存/喂养面板、每日衰减、介质材料消耗、兼容存档。
4. 验收：独立 Phase 5 测试接入 farmtest、失败零变更、往返存档、种植→收获→卖出/喂养→买种循环；当前资产和原逻辑回归，场景截图。

每批同类变更单独 Git 提交。原有种植生命周期和美术资产不扩展到 Phase 6。

## 验收清单

- 非法数量、余额/库存不足、未知商品/五行不符、未饿投喂均失败且无部分扣除。
- 每日与指定成功行为可叠加扣减；失败行为、未允许行为不扣减；归零钳制。
- 按公式向上取整；再生次数、生长时间、占地和介质成本均计入。
- 保存/读取经济状态一致；旧 schema 2 农场档默认 60 元石与满饱食度，重复读档不重复发放。
- 当前 farmtest、Python 工具测试、资产 QC 通过；历史场景仅单独回归，不混入当前默认测试。
