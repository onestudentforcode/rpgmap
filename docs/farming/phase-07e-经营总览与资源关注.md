## 1. 目标与边界

本阶段让玩家能回答三个问题：哪座设施需要处理、材料今天实际增减多少、三个时节的经营做了什么。完善现有管理窗口、设施详情和条目报告，不新增生产路线、人物、工种、物流、市场机制或独立模拟时钟。

| 内容 | 本阶段设计 |
|---|---|
| 养殖总览 | 每设施一行，集中查看个体阶段、维护状态、负责人、待收与阻塞原因，可定位设施 |
| 设施详情 | 保留动物/基础/特殊三栏，补齐混龄、原服务记录、投入报价与负责人状态 |
| 资源一览 | 沿用P7.b实际收支、历史均值及增长/负增长分组，接入P7.c/d原因 |
| 关注资源 | 玩家勾选、按槽保存；初始为空，空状态有用途说明和选择入口 |
| 记录 | 养殖与人工接入逐条日报、时节小结及首次45天回顾，不重复计算收入或支出 |
| 说明 | 可跳过、可重看，覆盖手动与负责人入口；不增加强制教学目标 |
| 美术 | 复用现有柔和明亮界面和紧凑图标，不生成本阶段正式动物/建筑美术，不增加音乐 |

本文不改变容量4、价格、供养值、配方天数或人工费。负责人按P7.d独占一座设施、成功工作才收费，V2取消固定雇佣人数上限的运行改造仍由P7.d实施；不恢复旧的“两人”“养殖工种”或跨设施优先级界面。

## 2. 导航、窗口与操作规则

沿用固定管理窗口，一次只打开一个经营页面。顶部导航通过紧凑图标进入养殖总览、资源一览等页面；窗口内可切换对应页签，不叠第二层经营窗口。主规格2560×1440，兼容1920×1080、1280×720及960×540紧凑布局，UI缩放100%/125%/150%。管理窗口以既有1040×780px为最大设计尺寸，随可用空间收缩并内部滚动。

功能按钮用简单图标，悬停约350ms或键盘聚焦显示名称和说明；动物/食谱选择、数量与页签保留文字。费用、投入、状态和不可操作原因直接出现在相关内容旁，不要求玩家靠悬停发现缺料。复用现有色彩与对比度规范，状态同时使用文字/符号，不能只用红绿区分。

打开窗口时阻断地图点击、农务快捷键与拖拽；输入数量/搜索时不触发地图操作。Esc沿用取消预览、关闭窗口、打开菜单的顺序。关闭普通窗口恢复原目标和视野；主动点击“定位”则明确切换目标和相机。所有查看、筛选、关注与定位均0AP、0元石，不结束当天。

## 3. 养殖总览

### 3.1 列表与设施定位

一座2×2设施按稳定设施UID只显示一行，不把四格当成四座圈舍/水场。页首显示设施数、在养幼体/成体数和待收数量；羊只与鱼尾分别列单位，不合成没有意义的产物总件数。初始没有设施时显示“建造圈舍或水场后，可在这里查看养殖和维护情况”，提供建设目录入口；进入建设不自动放置或扣款。

| 列 | 显示内容 |
|---|---|
| 设施 | 类型、短UID、位置；定位图标 |
| 在养 | 物种、总数/4、幼体数、成体数；待收个体是成体子集，不重复相加 |
| 今日维护 | 实际基础已服务数/在养数，剩余对象及当前可执行分支 |
| 生产 | 空闲/运行/待收的个体数量，特殊计划是否“暂不生产”，实际可收产物 |
| 水场条件 | 当前水体可用度、日结衰减后的预测值、低水阻塞；圈舍不显示虚假水指标 |
| 负责人 | 姓名、无人/专责/暂停，当前预算上限及实际巡栏条件 |
| 提示 | 缺料、低水、缺钱/预算不足等具体原因，或正常等待/无需服务 |

默认按设施UID排序，支持圈舍/水场、待收、需处理筛选及名称/UID搜索。筛选集合按当前状态重新计算，“需处理”是可说明的提示集合，不等于全部异常或强制任务。无匹配时保留筛选条件和清除入口，不显示成“没有建造设施”。

点击定位关闭窗口，以设施完整2×2范围为目标居中，并打开该设施详情。执行前按UID重查目标；设施已拆除则提示“该设施已不存在”，不按旧坐标选中后来建造的设施。历史报告同样遵守此规则。列表没有隐式批量喂养、批量购买或一键领料；实际动作在设施详情中执行。

### 3.2 待办、暂停与预估

界面须区分事实与计划，不能用单一红色“未维护”掩盖不同原因：

| 情形 | 表现 |
|---|---|
| 今天尚未喂，负责人可在日结处理 | “今日待维护 · 负责人X将在日结尝试”，并显示当前材料/费用；不说已经喂好 |
| 已经日结且当天缺料未服务 | 历史条目记“当天未服务，成长/周期暂停”，列实际缺口 |
| 玩家已经喂过 | “今日已喂”，可展开原玩家服务记录；当前食谱变化不重写记录 |
| 特殊分支缺料，基础分支成功 | 分开显示“基础已完成 / 新周期未启动”，不把全场维护写成失败 |
| 特殊栏“暂不生产” | 作为主动计划显示；已有周期继续、待收可领，不作为异常 |
| 无负责人 | 显示“手动维护”，可明确指派；不将无人一律判成停产 |
| 负责人暂停 | 显示“负责人暂停”，区别于动物因缺料/低水暂停；可继续手动 |
| 空场或今日无需新服务 | 普通状态，0人工费；不催促招聘、补料或用满工作额度 |

库存覆盖、预计完成日和巡栏费用都是基于当前共享库存/现金的条件预览，不预留材料，不承诺各设施同时满足。水场展示当前与日结预测值，报价使用P7.b/c同一条件判定。负责人费用沿用收取→必要修水→整体维护，一项成功1元石；“最多支出12”不等于“今日必付12”。

所有预览从模型只读查询派生，页面刷新不推进成长、生产或日结。待收/当日已喂按个体汇总，不用平均成长条隐去后购幼体；混龄细节交给详情最多四行记录。

## 4. 设施详情与订单提示

详情沿用动物、基础食物、特殊食物三栏；负责人放在其下方作为管理状态，不增加第四个食谱栏。首次自动选项明确提示所选物种与两种食谱，加载、缺料或开面板不静默重选。

在三栏后展示容量/混龄、今日基础服务、特殊周期、当前真实可领取量以及下一次操作报价。个体展开显示成长有效日或周期有效日、暂停原因、当天实际食谱和执行来源；改变计划后，原当天服务仍显示原食谱。水场另列水体维护，不将清水2并入鱼的每日基础餐。

操作区保留购买数量、整体维护、收取、水体维护和清退图标，直接显示成功AP/材料/费用及禁用原因。选择“暂不生产”时显示“停止新周期，已有周期继续”；当前计划与正在运行的实际周期食谱分开。清退确认说明在养数量、在制投入与待收产物将放弃，不退款、不伪造材料出库；非空设施不能直接拆除。

负责人区域显示专责身份、暂停与预算、成功工作1元石/无固定日薪、当前预计步骤。改派沿用P7.d明确提示旧设施或旧农务安排解除，不静默兼职。没雇工时提供雇工名册入口，并说明“招聘后需指派负责人；手动操作仍可使用”。

订单页继续显示五行、rank、需求值、所选合格食材、必要数量及回款拆分。钢绒与鱼肉仅在实际收取入库后参与持有量；在养动物、在制或待收不能直接交付。不自动收取/采购/选新食材，不因总览新增第二份交付接口。显示属性与食材资格的区别，未标记食材的粪肥不能仅因土属性供货。

## 5. 资源一览与主界面关注

### 5.1 保持统计口径

资源一览沿用P7.b完整资源账。默认是“今日实际，尚未结算”，也可看最近15个已结算日及最近最多7个已结算日均值；增长与平衡为净值≥0，负增长为净值<0。采购、销售和订单都算仓库入/出，负增长不自动等于亏损或断料。

周期资源只在实际领取日入库。成熟、加工就绪、动物待收不加入净增长；“待领取”及有条件的预计完成单列。均值包含零活动日，短历史用真实样本数，今天不混入历史均值；没有已结算日显示“暂无历史”，今日净0仍显示“平衡”。分组使用精确值，极小负均值不四舍五入成平衡。

P7.c/d扩展原因明细：基础食物、特殊投料、水体维护、剪毛/出塘、粪肥回收及负责人执行来源。元石单列真实收支，AP、水体、在养数量和供养值不当成材料；不把不同资源的件数相加成总净增长。

### 5.2 空状态与选择入口

**每个新游戏槽的关注清单初始为空。** 主界面保留一块窄关注区，显示：

```text
关注资源：在资源一览中勾选材料，查看库存和今日净增长。
[选择关注资源图标]
```

图标的悬停/键盘焦点说明为“选择关注资源 · 打开资源一览”。点击打开资源一览，资源行有明确“关注”勾选列；页首说明勾选结果显示在主界面。主界面空提示不是一次性教程，删掉最后一项、加载空清单或切到空的新槽都会显示，不靠提示已读状态永久隐藏用途。

只由玩家勾选，不自动添加牧草、清水、藻料或新获得资源。完整资源表的种子、材料、饲料均可选；动物个体、水体数值、AP和元石不加入物品关注列，元石仍由顶部状态栏展示。搜索/五行筛选隐藏某行不会取消已有关注，玩家也可选择“仅关注”查看全部已选项。

### 5.3 有关注项时

每项显示“小图标＋资源名/可识别短名＋库存＋今日净变化”，明确“今日”标签；正/负值带符号，0标“平衡”。悬停或聚焦补充今日入库/出库、最近7个已结算日均值及样本数、待领取量。点击该项打开资源一览并定位物品，默认看今日实际，不沿用上次历史日期误导为今天。

关注区不侵占地图工具或加宽状态栏。显示项数随窗口和UI缩放适配，超出部分收进“更多(N)”入口，打开资源一览的“仅关注”视图。**可见项数不是关注数量上限**，不因小窗口、缩放或切页删除清单。首次勾选按勾选顺序显示；取消后重选放到末尾，首版不增加拖拽排序。

空提示和“更多”均保持可用点击区；960×540可收为一行说明/入口，完整字段移至管理窗口滚动查看。注意资源名称、库存数位、负号和150%字体宽度，不仅测试空清单截图。关注项不出现自动采购、投喂、出售或结束当天的快捷执行动作。

### 5.4 保存与切槽

清单保存稳定物品ID及顺序，随所属游戏槽保存，与窗口分辨率/UI缩放等全局显示设置分开。勾选0AP、0元石，遵守日结束自动存档：下次日结持久化，不借此增加手动保存或即时游戏存档。

放弃未存的当天也回退当天关注修改，离开游戏按既有未结日规则提示；加载与切槽使用各自快照，不能沿用上一农场清单。保存失败保持当前清单，阻断与重试规则不变；重试不重复勾选或重新结算。

## 6. 逐条日报与时节小结

### 6.1 从实际事件生成

采用既有逐条报告形式，分类图标配短文字，按同一天的设施/物种、动作及原因聚合，必要时展开真实执行来源。记录来自成功模型事务和日结结果，不从界面按钮点击次数或日首尾差猜测。维护失败无投入/费用，基础成功而特殊失败则保留成功事实和未完成原因。

| 条目类别 | 必须区分的事实 |
|---|---|
| 购入 | 物种、数量、实际元石支出；购入不是育成或生产 |
| 维护 | 基础服务对象数/实际投入、特殊启动对象数/实际投入、水体维护次数；材料不重复累加 |
| 成长/生产 | 本日成年、周期有效推进、就绪待收；就绪不是入库或收入 |
| 收取 | 剪毛/出塘对象数、实际主副产物；鱼移除、羊保留 |
| 暂停/未完成 | 缺料、低水、负责人暂停/缺预算/缺钱等原因；主动“暂不生产”不是异常 |
| 清退/改派 | 已发生的数量或指派结果，保留历史来源，不给放弃产物虚构销量 |
| 人工 | 负责人及设施、实际成功步骤/总次数、实际人工费；预算另列 |

日结小摘要沿用普通窗口最多三条、紧凑窗口减少条目的布局。优先显示存档失败等阻断，再显示实际缺料/停工、待收等经营信息；未展示条目以“另有N条”进入记录。不要每晚逐个弹设施警告，也不要用当前状态把过去未维护的原因改写。第15/30/45天保留时节收支条目。

记录窗口仍保留最近15份完整日报，可按日期/类别查看；条目关联仍存在的设施可定位，已经清退的个体或拆除的设施只显示历史事实，不删除条目，不定位新对象。仅对确有稳定来源UID的条目提供定位，不由中文文字反推目标。

### 6.2 统计与现金对账

首次三个时节累计养殖购入、育成、剪毛/出塘次数和个体数、实际主副产物、基础/特殊/水体投入、负责人工作/人工费、暂停情况。服务对象数、成功操作次数及材料件数分别标单位；一次整场操作服务四只不是四次收费。

动物购入支出计入已有采购总额，负责人支出计入已有人工总额；养殖明细是这些总额的子项，不能在总支出中再加一次。自产饲料的消耗不是当日元石支出，材料出售机会成本与静态供养值不加入现金账；产物只有实际销售/订单结算时才增加现金收入。

现金仍满足“期初元石＋销售收入＋订单收入−采购−建设−人工＝期末元石”。资源按P7.b守恒。在同一事务中记录资源账、经营统计和执行结果，避免手动与负责人各自重复加账。报告保留投入与产出，不以净额抵销后隐藏消耗。

最近15日报不足以回放第1～45天全量行为，必须沿用并扩展**三个时节累计账**：成功事件先进入当日待结算账，日结将本日完整结果累加对应时节及分类材料量并封存；不能在第45天只对剩余15日报求和。投入等明细应复用同一事实来源，禁止把资源账出库与维护事件当成两份消耗相加。

## 7. 首次45天回顾与说明

第45天结束并完成当日结算后，沿用自动回顾入口，显示总计及第1/2/3时节页签。增加两条养殖路线的购入/育成/实际收取、投入材料、负责人支出和回流条目；仍无强制胜负、评分或养殖任务目标。若当次保存失败，优先保留阻断与重试入口，不让回顾遮挡错误；原样重试不重新累计或冻结一份新回顾。

期末分别显示元石、仓库材料、在养幼体/成体、待收主副产物及运行中周期摘要。仓库与未收权益不混为可出售库存，不把在养个体或材料估值加入“赚取元石”。羊剪毛后的在养量与鱼出塘后的数量必须反映真实不同结果。

45天回顾冻结三个时节账和当时的期末摘要；重看使用冻结值，不从后来第46天及以后的世界重算个体、库存或负责人情况。关闭后继续经营，日报和资源账继续滚动，当前养殖总览/关注条实时更新，首次回顾不再增加。

说明沿用可跳过、可重开的手册/上下文提示，覆盖建设与合法三栏默认提示、购入与基础维护、成体特殊投料/暂不生产、收取与粪肥堆肥，以及负责人指派/现金预算。说明手动成功耗AP、负责人日结计件收费，共享仓库无搬运。
