## 2. 三栏初始化与食谱切换

### 2.1 有提示的自动选择

新建圈舍默认钢绵羊＋牧草餐＋含铁补料；新建水场默认滤藻鲤＋藻料餐＋谷粒育肥料。默认项从该设施允许的物种及其配置中取值，优先采用显式默认ID；首版为上述确定组合，不依据当前库存暗中改选。

建造成功提示例如：“圈舍已建成。已默认选择钢绵羊、牧草餐、含铁补料；尚未购入动物或投喂。”设施详情在三栏附近保留“新建设施已采用默认配置”的说明，直至玩家明确修改配置。无需额外确认弹窗，打开面板、读档或缺料均不重新初始化计划。

缺牧草时显示缺料及谷粒餐可选提示，由玩家切换；即使仓库有谷粒，也不自动换餐。特殊食物栏明确本阶段尚不执行特殊生产，不能让自动选择看起来已启动生产。

### 2.2 保存与切换

- 食谱选择零AP、零材料、零元石，不推进时间；只接受该物种兼容的配置。
- 非空设施不能切换物种。空设施允许切换合法物种，重新选择兼容的默认食谱并提示具体变化；同一物种下不无故重置玩家选择。
- 原始数据的`base_diets`/`special_diets`当前是投入数组。实施时为食谱增加稳定ID和明确默认项，保持现有投入、周期和价格不变；保存ID，不把数组位置当永久身份。
- 切换基础食谱只影响下一次尚未服务的对象。当日已喂个体的服务日、原食谱及实际投入保留，不能再次扣料或多长一天。
- 同日补购的幼体尚未服务，按当前选定食谱计算；允许同一设施当天出现不同实际食谱。详情显示“今日已喂：牧草餐；后续计划：谷粒餐”，不将历史记录覆盖成新计划。
- 特殊栏按[P7.c](phase-07c-特殊生产与养殖回流.md)允许“暂不生产”，保存`production_enabled`及上次合法`special_diet_id`；默认仍有提示地选择食谱。配置只影响后续新周期，本阶段不启动生产。P7.c已定义实际周期投入与当前计划分开，不在本阶段提前实现状态机。

## 3. 个体、容量与采购

每座养殖设施使用**已有设施UID**作为身份，养殖记录引用该UID。占地、原点和设施类型由现有设施记录提供，不另外建立一套圈舍占地或`next_pen_uid`。动物有全局唯一UID，所属设施明确；每设施同种最多4只，幼体和成体一起计数。

| 物种 | 幼体价 | 成长目标 | 基础食谱，按个体/服务日 |
|---|---:|---:|---|
| 钢绵羊 | 12元石/只 | 6个有效日 | 牧草1＋清水1，或谷粒1＋清水1 |
| 滤藻鲤 | 5元石/尾 | 4个有效日 | 藻料1 |

购入数量为1～剩余容量的整数。报价显示数量、总价、购入后在养数量、当日尚未服务对象需求、明日起整场需求及成长期参考投入。元石不足、容量不足、物种/设施不符等整次失败，不部分购入、不生成UID、不扣款；成功整次扣款并新增幼体，0AP，不顺便投喂。

幼体不是共享仓库物品，不提供活体出售、运输或自由转移；成长为同一个体，不新增成体UID。动物购买单列元石支出和投放数量，不将其计入材料入库；水体指标也不计入清水库存。

### 3.1 饲料风险提示

缺料仍允许购买。购入前后提供以下只读信息，不能用未来收获替代当前仓库：

- **今日补喂需求**：仅计算当天尚未服务的个体；已喂记录保持原样。
- **明日起完整服务覆盖**：按购入后的全部在养数量和当前基础食谱，对各投入计算`floor(库存÷整场每日需求)`，取最小值。例：两只羊、牧草12和清水6，只能覆盖3次整场服务。
- **幼体剩余育成需求**：按每只剩余有效日汇总食谱投入；若今天已完成有效服务但日结尚未推进成长，扣除这一次已付投入，避免要求玩家再次备同一份料。
- **水场限制**：饲料覆盖与水体支持日数分别显示；水体维护的清水2另列，不合并为鱼的每日基础餐。预计缺水时提示先维护。

“育成需求”以之后正常服务、所选食谱不变为前提，不含成体后续维持、特殊生产、培养槽新批次投入或水体修复。库存是全农场共享的，覆盖值不锁料；其他农务、交易和加工消耗后实时重算。当天已服务且预计水条件有效的个体显示“今天已喂”，缺料告警指向尚未服务对象和未来，不误报为今天没喂。

## 4. 基础服务、成长与水体

### 4.1 整体基础维护

一次手动维护以该设施全部“当日尚未服务”个体为对象，包括成体。先检查所有对象及完整基础投入，整分支原子扣料、逐个登记实际服务。库存不足不只喂其中一只，不扣料、不扣AP、不留下半完成记录。

成功一次扣1AP，与对象数量无关；全部已服务、空场或条件不符均不构成工作，0AP。当天补购幼体后可再维护，只服务新增对象；不是设施每日至多点一次。服务记录及资源账必须写入后再扣AP，保证最后1AP触发自动日结时仍算当天投喂。

本批只有基础分支。P7.c接入特殊分支后仍用一次整体维护，不将未来两个有效分支收费为两次；当日基础已喂而特殊未投的合法重试，需保留原基础记录。

### 4.2 日结成长

服务日采用`D=clock.total_days`，界面显示第`D+1`天；日变更回调收到`n`时，结算的是`D=n-1`。当日新购幼体若已服务且水条件有效，可计一个有效日；没服务则不成长。

成长进度使用整数，正常有效日增加100，羊目标600、鱼目标400。达到目标进入成体，保留UID并封顶；缺料/缺水日增加0，不清零、不死亡。日结开始为幼体的个体只结算成长，刚成年不在同一天再跑特殊周期。

成体每天仍需基础维护，但P7.b不生成钢绒、鱼肉或粪肥。显示“成体，继续基础维持；特殊生产待后续接入”，避免玩家把无产物误认为操作失败。现实等待、展开个体、预览和存读档均不增加有效日。

### 4.3 水体可用度

复用P7.a已配置的初值：新水场100，上限100；仍有在养个体时每次日结减5，再以衰减后数值判定，**≤30暂停全场成长**。空场不衰减，不通过购买或清退将已有水体自动重置到100。

手动水体维护需有动物且指标未满，消耗清水2＋1AP，增加40并封顶100。清水不足或无对象时零改动。整体投喂报价先预测日结衰减：如当前35，日结为30，则提示“本次投喂不能支持成长，请先维护水体”，投喂不扣料；维护后重新报价。

从100开始连续不维护，第13次日结为35仍有效，第14次为30暂停；界面不误写成14个有效成长日。雇工阈值60保留已有配置，到P7.d接自动维护。水库本身不生成可交易清水，不做额外水体指标。

### 4.4 日结顺序

复用统一时钟，将养殖结算接在雇工之后：

`雇工 → 水体衰减/暂停判定 → 养殖成长/维持结果 → 作物与环境 → 资源额度刷新 → 加工就绪 → 订单推进 → 日报与资源账封账 → 同一快照自动保存`

P7.b雇工仍只做既有工作。加工就绪只是转成待领取，未增加仓库就不记入库。保存失败阻断操作；重试只保存既有结算结果，不重复投喂、成长、扣水、封账或收费。读档整体恢复所有记录，放弃当天也一并恢复资源账。

## 5. 设施详情与安全退出

面板仍只有动物、基础食物、特殊食物三个配置栏位。状态与操作放在其旁边或下方：

```text
圈舍 · 3/4只 · 幼体2 / 成体1
[动物：钢绵羊] [基础：牧草餐] [特殊：含铁补料]
今日已喂2/3 · 本次补喂：牧草1 + 清水1 · 成功1AP
明日整场需求：牧草3 + 清水3 · 库存覆盖2次服务
[展开个体] [手动维护图标] [清退图标]
水场另显示水体当前值、日结预计值与维护图标
```

展开后最多4行，每行显示短UID、幼体/成体、成长`4/6有效日`、当天是否已喂及实际食谱。已成年无需继续显示虚假的成长倒计时；暂停说明同时列缺料/水体原因。只有真正存在多种状态时才显示分组，不用平均成长条掩盖最晚入场幼体。

按钮保持小图标，悬停说明功能、材料/AP和不可操作原因。购买支持数量，配置与只读查看0AP。点击2×2任一格指向同一设施；UI重建或更换目标后再次核验UID，不能对已拆设施执行旧按钮。

清退需确认整个设施的动物数量；成功移除全部动物，1AP，不退款、不返饲料、不产物。设施、水体和配置保留；空场再次清退失败0AP。非空设施不可直接拆除，清退后沿用已有手动拆除。P7.c接产物后补齐待收权益和在制投入的放弃提示，本批不制造尚不存在的产物。

## 6. 模型与持久化建议

养殖独立模块接入V2世界，不复制V1土地、加工、库存和经济。共用世界需要扩展时增加受控的可选接缝，V1不开启养殖或新资源账。下列名称为拟建字段/模块，不是已实现入口。

```text
world.husbandry:
  habitats: [{ facility_uid, species_id, basic_diet_id,
               special_diet_id, production_enabled, default_notice,
               individuals: [{ uid, stage, growth,
                 base_service: { day, diet_id, inputs, operator } }],
               water_available }]  # water仅水场使用
  next_animal_uid
resource_ledger:
  pending: { day, opening, inflows, outflows, reasons }
  history: [{ day, opening, inflows, outflows, closing, reasons }]  # 最近15日
```

`base_service`保存最近一次实际服务：从未服务时day=-1、食谱/投入为空；服务成功记录零起始D、当时的稳定食谱ID、按个体实际扣料及执行来源。本批来源为玩家，后续雇工使用同一结构；旧服务日不是今天就不视为当天已喂，切换计划不修改这份事实记录。周期字段在P7.c真正接生产时增加，不提前填入一套无法运行的生产状态。

建议P7.b将V2快照版本从现行7递增至8，产品和三槽目录不变；加入养殖与资源账后旧schema7拒绝并提示重新开档，不自动迁移或覆盖。**本次文档修改不更改实际schema7代码**。后续扩展同样按契约变化决定版本，不在草稿中宣称未来版本已可加载。

校验必须覆盖设施一一对应、全局个体UID唯一/计数器单调、物种及食谱兼容、容量4、合法阶段和进度、服务日与实际食谱投入一致、仅水场水体0～100。同日已服务记录允许与当前计划不同；不得误判为坏档。养殖设施禁止挂加工批次，所有关联和资源账合法后才修改活世界。

## 7. 资源一览设计建议

### 7.1 默认回答“仓库今天实际增加或减少了多少”

沿用固定管理窗口，增加“资源一览”入口，以小图标和悬停说明进入；不挤进设施详情或另开第二层经营窗口。默认两组表格可滚动，搜索/统计口径保持在顶部，点击资源行展开收支原因。

每种资源独立记账；界面列名为“净增长”，定义为实际库存净变化：

`每日净变化 = 当日实际入库 − 当日实际出库`

`期初库存 + 入库 − 出库 = 期末库存`

默认页显示**当日实际，尚未结算**，实时更新；可选择最近15日任一已结算日。两组固定为“增长与平衡（净值≥0）”及“负增长（净值<0）”，零值带“平衡”字样并归前组。按当前所选统计口径分组；不只显示有库存的材料，完整资源表中的种子、材料、饲料均可查看，支持名称搜索及五行筛选。

每行显示名称、当前库存、所选日期入库、出库、带正负号的净变化。历史日期查看时明确“当前库存”与“所选日期期末”是不同字段，不能将今天库存冒充昨天期末；当日页期末为“当前”。展开一行看来源/去向：

负增长表示该统计窗口内库存下降，可能来自正常销售、投料或收获间隔，不自动等于生产亏损或即将断料。经营风险结合库存覆盖和待收批次提示，不能给所有负数统一挂“缺料”告警。

| 入库来源 | 出库去向 |
|---|---|
| 自然资源采集 | 播种及培养料 |
| 作物收获/采脂/砍伐 | 浇水、施肥 |
| 加工实际领取 | 加工启动投料 |
| 养殖实际收取（P7.c接入） | 基础食物、特殊补料、水体维护 |
| 市场采购 | 建设材料、市场出售、订单交付 |

采购增加材料、销售和供货减少材料，必须计入仓库净变化，同时标明经营来源，避免把买来的料当自产产量。元石单列真实收入/支出/净额，复用经营现金账；动物个体数、水体可用度、AP、供养值与材料件数不混加。不同资源不相加成一个没有单位意义的“总净增长”。

### 7.2 周期材料：事实与趋势分开

**实际账只在收获、领取入库时计增长，不把未来产物提前平均进每日库存。** 播种时种子减少，加工启动时投入减少；作物成熟、批次完成或动物进入待收均不产生材料入库。玩家延迟收取，就在实际领取的那一天记账。

另提供“最近7日均值”视图：将最近最多7个**已结算日**的入库、出库、净变化分别求和，除以真实记录天数。包括没收获、没操作的零变化日，不仅除以有收获的天数；未结算的今天不混入，开局没有历史时显示“暂无已结算日”。数据不足7日显示实际样本数，例如“最近3日均值”。仍按均值净额分两组。

| 情形 | 当日实际 | 均值/补充信息 |
|---|---|---|
| 藻槽启动 | 清水−3、秸秆−2；藻料0 | 仅说明已有批次，不计预计藻料6 |
| 两日后完成但未领 | 藻料0 | 显示“待领取6”，不算库存或增长 |
| 当日领取藻料6，喂两尾鱼消耗2 | 藻料入6、出2、净+4 | 若连续两个已结算日数据为入6、出4，则两日均值入3、出2、净+1/日 |
| 同一天买谷粒2又用掉2 | 谷粒入2、出2、净0，归增长与平衡 | 展开仍能看到采购及投喂，不省略成“无活动” |
| 7日内尚未砍成长期杉木 | 原木实际和7日均值可均为0 | 不凭未来砍伐给每天虚构正增长 |

均值是历史观察，**不是明天承诺产量**。长周期或首次启动可能尚无收获，详情保留最近15日逐日记录；后续可增加15日均值和图表，但无需首版做复杂趋势图。

待收产物独立显示“可领取数量”，在制批次显示其预计完成时间，不加入净额。P7.b先使用已有加工批次及作物状态；动物周期预测由P7.c接入。理想吞吐如藻槽6/2=3份/天只属于配方说明，前提是及时领取、重新启动且持续有料/AP；不得当成仓库实际日增。鱼的一次性出塘还包括育成及重新购买，不可仅用育肥2天算持续产能。

数值分组先用精确净额再格式化；均值最多显示两位小数，极小负数显示“−<0.01/日”，不能四舍五入成0后误放平衡组。当日整数收支直接显示整数。

### 7.3 统计基础与一致性

现有`v1_journal.gd`只有部分产量/现金计数，不包含完整材料出库或采购数量；不能直接拼成全资源净增长。建立V2资源账，在**成功的模型事务**中记录带原因的实际投入/产出，再通知UI或扣AP。手动与原有雇工都经过同一记录接缝，UI不自行推断。

- 初始赠送库存作为期初，不是第一天生产收入；存档恢复/撤销当天不是新的入库或出库。
- 失败与取消没有流水；清退只减少动物，不把未产生的材料虚构成资源出库。后续特殊分支失败只记录实际成功的基础投入。
- 同次交易可同时有入/出，以实际量分别累加。不能仅靠日首尾库存差推导来源，否则会丢掉“买2、用2、净0”的事实。
- 原因明细按日、资源、原因及必要来源聚合，保留最近15个已结算日和当日账，不无限增长；净额与均值由非负整数入/出派生，不另存易失配的浮点净值。
- 资源账`day`统一使用零起始服务日D，显示时加1；当日pending为D，历史最新日为D−1。与已有从第1天标记的日报按显示日关联，不靠混用两种日期“修正”缺一天的账。
- 历史来源UID只用于解释已发生行为；拆设施/清动物不删除原流水，不要求历史来源仍在当前世界存活。校验来源结构与资源/原因是否合法，不重新执行历史动作。
- 日结核对每项库存守恒、上日结存与下日期初连续、当前账日期/库存一致。内部对账异常必须阻断保存及后续操作、保留诊断，不执行普通保存重试绕过校验，不能用一笔不明“调整量”补平。
- 保存失败原样重试不会新增流水；装载先校验完整账与库存再应用。第45天后资源账继续滚动，首次45天回顾仍按现有规则冻结，二者生命周期独立。

资源一览是只读经营信息，不通过打开页面触发领料、投喂、采购或结束一天。共享库存的消费记录有实际执行顺序，不引入仓库预占或物流。

### 7.4 后续主界面关注资源

资源行预留“关注”勾选位，P7.e接入主界面窄条。仅由玩家勾选，**每新槽初始为空，并在主界面说明用途和提供选择入口**，不自动添加牧草/清水/藻料；稳定物品ID和顺序随所属游戏槽保存，切槽不带入另一农场清单。无手动保存，修改在下次日自动存档持久化；空提示、更多和取消最后一项细节见[P7.e](phase-07e-经营总览与资源关注.md)。

主界面每项显示“小图标＋库存＋今日净变化”，悬停补充今日入/出、最近7日均值、待领取量；标签明确“今日”，不与均值混用。点击打开资源一览定位该材料。关注数量不设玩法限制，屏幕显示不下时收进“更多”，不通过扩张顶部栏遮挡地图；兼容窗口同样保留工具栏和状态条空间。

关注UI和用户偏好字段等到P7.e真正使用时接入，P7.b不加入无用途存档空字段。未来可以追加可得库存、计划消耗、长期趋势或自动化预估，但各项与“实际收支”保持独立口径，不静默替换净增长定义。
