# Demo V1 — 农务雇佣与任务标记

> 2026-10-10。用户已确认：当前雇佣普通人，不引入蛊虫特殊单位；任务标记、个人工作偏好、地格选种与日结收费首批已实现。独立入口：`play.bat v1`，存档目录仍为`user://farm_demo_v1_slots`。作物/设施使用文字灰盒，正式美术、45天回顾与发布包尚待后续。

## 1. 操作入口

展开画面底部的“农务工具”，选择工具，再框选地格。工具只添加待办标记，不立刻操作、不扣玩家AP；不适用的地格跳过，显示新增/跳过数量。标记优先级为1～9，重复框选同类型目标更新优先级，不重复生成任务。

| 工具 | 标记条件与执行结果 |
|---|---|
| 开垦 | 可种植的空闲野地；完成后恢复为空闲耕地 |
| 播种 | 已开垦地格，仍须该地格已分配种子和有完整投入；缺料等待 |
| 收获 | 麦/菌菇收获，以及松脂树留树采脂；可提前标记未成熟作物，成熟后执行 |
| 浇水 | 耕地/作物地格；水分低于30才执行，每次照常消耗仓库清水 |
| 施肥 | 耕地/作物地格；肥力低于30才执行，每次照常消耗仓库腐殖土 |
| 砍伐 | 速生杉或松脂树；成熟后取材并移除，不同时采脂 |
| 清理 | 移除当前作物，允许未成熟；不产出、不返还种子/培养料，释放整个占地 |
| 取消标记 | 删除框选范围内的手工待办；不删除地格选种计划 |
| 负责区域 | 为当前选中雇工追加一个负责区域；同一人可负责多处，允许多人区域重叠 |

按用户补充统一“收获”，不再单列“采集”农务工具；木材取得走“砍伐”。收获/砍伐/清理在同一作物锚点互斥，后添加的操作替换前一个，避免先收又清等冲突。多格作物触及任意占地时，作物操作归到原点，只执行一次；浇水/施肥仍逐格处理。农务任务按原点是否在雇工负责区域决定其是否可接。

开垦、显式播种、清理完成后移除标记；收获、砍伐、浇水、施肥委托持续生效，当前不满足条件则等待。作物消失或改变后重新判断适用性，不凭旧标记发产物或收费。玩家仍能在地格面板手动操作，成功照常消耗AP；标记不会占用土地或预扣原料。设施建设、拆除、加工启动/收取仍由玩家操作，本批不派工。

## 2. 地格选种与资源点

点击地格可分配植物种类，计划按该植物完整占地校验，不能与其他选种计划重叠；已有作物不会立即换种。设定只记录意图，不扣种子。空闲耕地在雇工负责区域内时自动产生播种任务；收获/砍伐/清理后，原计划保留，种子与全部培养投入足够才重播。

缺种、缺木屑、缺清水时等待，不自动购买；没有雇工或无人负责时也不自动播种。手动种植同样读取选种计划。取消手工标记不取消选种；想保持空闲，需在地格面板选择“不播种 / 保持空闲”。清理工具和地格面板均提示这一点，避免清理后自动重播造成误解。

资源点不通过农务工具栏框选。点击采石/采矿/泉水点，在面板指定一名雇工或“不分配”；同一人可兼管多个资源点。该派工不受农务负责区域限制，但仍受个人工作偏好、预算和工作量限制。手动采集与雇工共享当天剩余产能；雇工执行后才刷新次日产能。

所有种子、培养料、清水、肥料与收获直接进出共享仓库。不实现携带、搬运、路径或人物实体；地图只显示任务边框/类型/优先级、选种标记、负责区域高亮和资源点分配标记。

## 3. 雇工与调度

最多2人，初始无人；雇佣/解雇不收费，无固定日薪。每人每日最多成功12次，默认日预算12元石，成功一次收费1元石，不消耗玩家AP。预算可设0或更高，实际工作量仍最多12次；不提前冻结预算。姓名、暂停、预算、各类工作偏好、区域、资源点分配均随槽保存。

个人工作偏好0～5：0禁止，5最高，允许一人做多种工作。任务选择顺序为：个人工作偏好→标记优先级→默认类别顺序→稳定目标次序。默认类别顺序为资源采集、收获、开垦、播种、浇水、施肥、砍伐、清理；默认个人偏好均为3，玩家可以调整，不把“默认顺序”当成不可变职业。

参考依据：[Klei官方更新258691](https://kleiforums.com/game-updates/oni-alpha/258691-r386)明确区分个人工作优先级与任务紧急度。本模块借鉴双层设置；0～5/1～9的数值、日结执行、同分排序和轮流接单均是本项目规则，不宣称完整复刻《缺氧》的实时调度。

日结中按雇工编号轮流，每轮每人最多成功一次；每次操作前重新检查土地、作物、投入、钱包、预算和资源配额。重叠区域不会对同一已完成操作重复收费；等待成熟、养护条件未触发、缺料等失败不收费、不占成功次数，继续找其他可执行工作。无钱/预算用尽停止该人的工作，另一人仍按自己的预算尝试。

计费单位：开垦/养护一次按一格；播种/收获/砍伐/清理按整株；资源采集按一批（例如泉水一次5份），不是按材料单位收费。四格树只砍一次，四格逐格养护则分别收费。实际人工费用不修改静态供养值。

## 4. 日结与存档

顺序：雇工处理当天任务→作物生长→逐格水肥消耗→资源点配额刷新→加工到期→归档完成订单/生成次日订单→一次完整日存档。雇工浇水/施肥影响本次生长；本次日结才成熟的植物留到下次雇工结算收获。手动休息、末AP自动过日使用同一流程，不为雇工另推一天。

schema 5新增完整`workforce`：雇工、负责区域/个人偏好、资源点指派、待办标记、选种计划、下一编号、累计人工支出、上次日报。日报保存成功工作类别/次数、费用和停工原因。重载不重复劳动或收费；弃日同步回退当天标记、选种、雇佣修改、库存、劳动结果与元石。

日存档失败阻断后续农事、交易和雇工设置；重试只保存已结算状态。仅旧V1 schema 1～4补空雇工系统，schema 4既有订单历史、元石和生产状态原样保留；仍不导入V0存档。固定三槽独立，不能指定别的槽提交当前农场。
