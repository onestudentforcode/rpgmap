## 1. 目标与规模

在已完成的种植、畜牧、水产、加工和五行供货上，让玩家组织三组生态：**花源/授粉/油料、水产/净化、岩石破碎/选矿**。饲料和少量灵食加工承接产物，研究逐步开放工艺，辅助设施承担重复维护。

首45天仍生成一次冻结回顾，之后继续经营。前45天能建立初级生态；本轮用120天补验完整研究网、三组生态、高级加工消费和收入再投资，保留90日检查点，不要求45天解锁全部第三层研究，不设强制胜负。

| 内容 | 已确认边界 |
|---|---|
| 新物种 | 核心6种：蜜铃灌木、油籽花、净水菌毯、蜜盏蜂、岩腹兽、啮岩鼹 |
| 新设施 | 8类：研究台、蜂箱、农产加工台、净水菌床、岩兽工作场、厨房、田间维护站、补光灯 |
| 研究 | 实体研究台、三层、8～12项目；本稿编排12项 |
| 加工 | 20～30条有效工艺、主线深度3～4；本稿列24条，堆肥换料另列 |
| 环境 | 既有水分、肥力、固定自然光照、独立水场状态；新增花源供给、净化能力、矿料约束 |

## 3. 网络、单位与设施职责

采用**一张跨模块生产关系网＋一张研究前置图**。资源网允许回收循环，研究前置必须无环。种植/畜牧/水产/工业与五行是浏览筛选，不切成互不相通的科技树。工艺解锁能力，设施提供执行条件，配方定义精确投入产出。

设施使用“主类别＋功能标签”，不要求类别互斥：

| 主类别 | 职责 | 例子 |
|---|---|---|
| 生产 | 从环境、种植或养殖获得产物 | 耕地、资源点、蜂箱 |
| 转换 | 改变材料形态或用途 | 堆肥、炭化、净化 |
| 加工 | 按已掌握配方制造材料/灵食 | 农产加工台、冶炼炉、厨房 |
| 增幅/光环 | 覆盖区域内改变条件 | 补光灯、授粉效果 |
| 研究 | 消耗样本，解锁设施/工艺 | 研究台 |
| 维护/服务 | 执行浇水、施肥等实际操作 | 田间维护站 |

冶炼可同时带转换、加工标签；蜂箱兼具生产与授粉。分类不赋予隐含属性转换或额外产量。

一群蜜蜂是一标准单位蜜盏蜂，羊以头、鱼以尾、菌毯以培养单位计数。数量统一为整数标准单位，不模拟单蜂，不把成长复制成新单位。物料“份”是配方单位，不等于统一重量；矿物关键成分另有审计系数。

## 4. 三组生态的执行契约

### 4.1 有限花源与授粉

只有处于供花阶段、环境正常的蜜铃灌木和油籽花供花。每株每天有限花蜜/花粉份额，**蜂群利用与玩家采集共享同一份额**。未使用份额当日失效；切换工具、移动蜂箱、存读档或重复维护不刷新份额。

蜂箱只利用覆盖内花源，不用仓库花蜜替代本阶段的附近花源要求。实际利用花源才产生授粉记录，同一作物同一周期的增益不因多个蜂箱叠加。油籽花收获增益设上限；不泛化为全地图作物增产，也不让增益扩大花源份额形成自增强循环。

显示可供花株数、今日剩余份额、蜂群需要量和缺口。手采所得才进入库存日账；蜂群内部利用记录为生态流量，不能同时登记成“仓库收到花蜜”和“蜂群消耗仓库花蜜”。调度按稳定顺序竞争剩余份额，成功利用时原子登记来源株UID、日期和服务单位。

### 4.2 独立水场与实物污水

每座水场保留自己的水体可用度，20×8水库只规定建造区域。水场有动物、状态未满且**实际成功换水**时，消耗清水并产生对应数量的污水。衰减水体数值、反复点状态、空池维护、失败动作或无消耗配置切换均不产污水。

净水菌床从仓库取污水，消耗加工投入、有效维护日并回收部分清水与污泥；回收量小于污水投入，有损耗。清水继续用于种植、养殖；污泥回堆肥；进阶工艺把部分污水变成营养液用于高密度藻料。不把已有鱼粪再隐式复制成污泥。

显示本批投入、预期回收、处理进度和暂停原因。基础泉水与既有藻料路线一直可用，净水是补充循环，不成为早期唯一水源。

### 4.3 有投入的岩石产业

啮岩鼹的菌菇/水是基础维护食物，石材/矿石是加工投入，两栏职责分开。岩腹兽吃草料/水，只有实际投入含铁矿料才产富集矿砂与尾砂。基础维护不会凭空产矿。

破碎、富集、冶炼按矿物关键成分审计，金属可回收量不得超过真实投入。尾砂、炉渣可作建材填料，本阶段不能再次抽取金属。钢绵羊新矿质补料也需矿料投入，不因动物数量或配方次数增加金属凭证。

## 5. 研究与持续生产

### 5.1 有效研究日

启动项目一次扣元石与材料样本。每个有效日完成一次研究工作：手动1AP；雇工占一次成功工作且付1元石。每台每日最多推进一次、同时只研究一项目；三层初值2/4/6有效日。不安排工作就暂停，反复点击无额外进度。

已完成研究全农场共享。一个项目同时最多由一台研究台承担，不允许并行重复扣费/解锁。不同项目可并行；暂停保留投入与进度，首批不做取消退款或跨台转移。样本必须来自默认工艺或前置研究，不能要求本项目才开放的产物。

### 5.2 目标库存与保留量

每设施选择配方、持续生产开关和主要成品目标库存，默认关闭，空配置说明用途。达到目标停止**新投料**，在制批次照常完成；收取仍需实际动作。自动判断统计仓库数量和全农场同成品在制预计产量，避免多机各按库存缺口重复开批；允许最后一整批的小幅超额，不拆配方。

原料保留量为全农场自动加工策略：投料后库存不得低于保留量。只约束自动加工启动，不阻止玩家手动投料、交易、研究、基础养殖维护或建筑；界面明确此范围，不能暗示仓库材料被锁定。每次自动投料在实际执行时重验共享库存，不预先赊欠原料。

原料不足、未解锁、缺有效培养/工作单位、目标已满足、预算或额度不足均显示不同暂停原因。目标不是销量承诺，不能把预计产量记作实际资源增长。

## 6. 一人多设施与兼任调度

P8明确替代P7“一人一设施、不兼职”的限制；不引入新工种或特殊蛊虫单位。

- 一个雇工可显式负责任意多设施，每设施最多一负责人。重新指派保留已完成服务、批次及当天账目。
- 所有负责设施及兼任任务共享**12次成功工作/日、个人预算**，同时受全农场可用元石约束；无固定雇佣成本。
- 设施设高/普通/低优先级。每人兼任农务默认关闭，开启后必须选择农务范围、任务类别及资源点；关闭不撤销其他玩家委托标记，不自动扩大范围。
- 一次整体养殖维护、一批投料、一批收取、一次研究工作各算一次成功工作。田间人工仍按既有每格动作计费；辅助装置自行运行只扣实际材料，不伪造雇工工作或玩家AP。
- 候选任务先验证合法性，再按优先级安排；同优先级内先处理维持/可收取任务，再研究、投料和农务，重复同类任务以等待日和稳定UID轮转，避免一个多任务设施永久占满额度。
- 失败不扣钱、不占成功额度；暂停原因进入积压列表，同次日结对相同失败条件不反复重试。玩家当日已做的服务不会由雇工再收费。

管理页显示每人的关联设施、兼任范围、已用/剩余额度、预算及积压，提供定位和重新指派。预计工作量分“当前可执行”和“条件满足后可能新增”，不能把未成熟、缺料或未来研究日误算成当天必收工资。收费记录能追溯到雇工、设施/地格、任务及日期。

## 7. 辅助设施、日结与资源账

田间维护站复用既有按**地格**浇水/施肥的材料量和增量。只服务覆盖内低于设置阈值的已开垦地格；覆盖重叠不能在同一地格同一服务项目重复扣料。补光取自然光与有效灯光的最大值，不叠加；照亮喜阴菌菇可能降低效率，必须预览和提示。燃料明确列为物品投入，不因为材料有火属性就自动可燃。

已采用以下日界顺序，并通过候选保存事务及各生态/装置边界测试：

1. 服务日D开始，启用装置按配置执行一次灌溉/施肥与灯光燃料结算；当天新建或修改配置次日运行，UI提示生效日。
2. 玩家手动操作D，使用D的花源剩余份额和灯光状态；日结时雇工执行剩余任务及维护。
3. 推进有实际服务的生物/净化/研究，以及既有按天加工；完成物料保持待收取。研究成功动作只给当天有效日，不重复推进。
4. 冻结D的资源账、条目报告、时节累计及第45天回顾，再开启D+1装置结算与日账，最后写所属槽自动存档。

事务记录包含已运行装置、实际服务、花源分配、研究日标记、共享额度、扣费及库存流。读档不再次执行开日动作。保存失败必须恢复完整日结前状态，包含回顾/奖励/扣费，重试不能双扣或双产；第45天回顾取D结束快照，不混入第46天装置消费。

资源一览继续显示实际入/出库、净值及7日历史均值：净值≥0放增长栏，<0放负增长栏。花源内部利用、成熟待收、预测净化能力单列；水体状态不伪装成清水库存。新增原料、研究样本、设备消耗可关注，初始关注仍为空，随槽保存。
