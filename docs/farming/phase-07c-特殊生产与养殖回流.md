## 1. 阶段目标与边界

P7.b负责幼体购买、基础服务、成长、水体和资源账；P7.c让成体开始消耗特殊投入，完成钢绵羊剪毛和滤藻鲤出塘，并将实际获得的副产物送入堆肥、回到种植。

| 内容 | 本阶段范围 |
|---|---|
| 特殊计划 | 三栏中的特殊食物可选食谱或“暂不生产”，选择本身不扣料/扣AP |
| 整体维护 | 基础与特殊分支共用一次动作；分支各自原子执行，成功一次只扣1AP |
| 生命周期 | 成体空闲→周期进行→待收；缺基础料/水暂停，已投特殊料不重复消耗 |
| 收取 | 羊剪毛保留成体，鱼出塘移除成体；按设施一次收取全部待收个体 |
| 回流 | 羊粪肥/鱼粪堆肥→腐殖土→实际施肥；复用现有堆肥模型 |
| 经济 | 新产物可出售或按既有资格供货；静态供养值不随实际操作变化 |
| 资源信息 | 接入特殊投料、养殖收取及待收信息，延续真实日账与7日均值口径 |

圈舍/水场容量仍4，只购买幼体，无繁殖、死亡、寿命、人物、物流或仓储限制。养殖雇工在P7.d接入，完整报告/关注资源条在P7.e，首次45天体验和发行交付在P7.f。本阶段不新增自动买苗、自动采购、自动启动加工或自动出售。

## 2. “暂不生产”与特殊计划

特殊食物栏在合法食谱外增加“暂不生产”。默认仍沿用P7.b有提示的自动选择：羊为含铁补料、鱼为谷粒育肥料；玩家选择“暂不生产”后保留该选择，不因有料、空场、收取或读档自动恢复生产。

| 当前个体状态 | 选择“暂不生产”后的行为 |
|---|---|
| 幼体 | 继续基础维持与正常成长，不投特殊料 |
| 成体空闲 | 只做基础维持，不启动周期、不产物 |
| 周期进行 | 已投入食谱和产物不变；基础服务与水有效时继续推进 |
| 待收 | 已完成产物仍可收取，等待时仍需基础维护；收取后不启动新周期 |

配置提示：“已停止启动新周期；已有周期仍按原投入继续，需要每日基础维护。”这不是暂停全部养殖的开关，不暂停幼体成长、不清进度、不退款、不把已投入原料退回仓库。

选择合法食谱恢复生产计划，下一次玩家整体维护或后续雇工巡栏才可能投料；配置、日结、成年、收取和打开面板都不自行启动周期。没有新服务对象时恢复计划本身也不收费。

建议持久化采用`production_enabled`加保留的`special_diet_id`：选“暂不生产”关闭前者，保留上次合法食谱供恢复；选食谱开启前者。两个字段仍属于同一个特殊食物栏，不增加第四栏。运行周期记录实际食谱，与当前计划分开；以后扩展多种食谱时，切换只影响新周期，不能改写已投入周期。

“未启动：缺特殊料”与“暂不生产”分别展示。主动停止生产不报缺料告警；已运行周期也不会因仓库缺新一轮特殊料而暂停。

## 3. 特殊生产配数与有效日

### 3.1 两条路线

| 物种 | 启动时投入，按成体 | 周期 | 每次实际收取产物，按个体 | 收取后 |
|---|---|---:|---|---|
| 钢绵羊 | 含铁矿石1 | 3个有效日 | 钢绒1＋羊粪肥1 | 成体保留，回到空闲 |
| 滤藻鲤 | 谷粒1 | 2个有效日 | 鱼肉3＋鱼粪1 | 原个体移除，释放一个容量 |

特殊料只在周期启动时扣一次，运行中不每日再扣。有效日仍要求当日基础服务完成；鱼还要求日结衰减后水体可用度>30。缺基础料或水体不足只保留进度，补齐后继续；缺下一轮特殊料不会影响已投入的一轮。

周期进度正常每个有效日增加100，羊目标300、鱼目标200；封顶后进入待收。暂停是由当天服务/水条件推导的原因，不另造一份会与进度失配的永久“暂停阶段”。

### 3.2 启动与成年时点

启动对象为该设施**已经成年、周期空闲、当天基础服务有效**的个体，且特殊生产计划开启。幼体、运行中和待收个体均不重复投特殊料。

服务日沿用`D=clock.total_days`、界面第`D+1`天。当天开始时已成年且完成基础/特殊服务，可以在当天日结推进一次周期；日结刚成年的幼体只完成成长，最早次日维护才启动特殊周期。

同一天剪毛后，原羊若已获当天基础服务，可再次整体维护只启动新周期，基础料不重扣；该次成功动作另扣1AP。日结只推进当前存在的周期一次，不因为两次维护多长一天。鱼出塘后不自动补苗，购买新苗仍走P7.b采购事务。

### 3.3 主副产物时点

钢绒与羊粪肥、鱼肉与鱼粪各属于同一周期的主副产物，不因基础维护、成年或等待额外每日产出。日结完成只登记待收权益；实际收取才进入共享仓库。

待收个体继续占容量和需要基础料，水场仍按在养情况衰减；缺料或低水不抹掉已完成产物，收取不受当天基础服务/水体暂停限制。羊待收时不叠加第二轮钢绒；鱼不能同时留在水场并作为鱼肉入库。

## 4. 整体维护的两分支事务

沿用一个整体维护按钮，报价逐项列出服务对象、投入和分支结果，不拆成两个固定收费按钮。

1. 校验设施身份、存档阻断与手动AP；水场预测日结衰减后可用度，≤30时先提示水体维护，投喂零改动。
2. 基础分支计算全部当天尚未服务的在养个体，按当前基础食谱检查完整投入；够料则整分支扣料并登记原服务，不够则整分支失败，不部分喂养。
3. 特殊分支在基础结果之后重新计算：当前计划开启、成年空闲且当天已完成基础服务的全部个体。按适用总数与**扣基础料后的剩余库存**检查特殊投入，够料整分支启动，不够整分支失败。
4. 提交实际投入、服务/周期记录及资源流水后，再按此次是否有有效工作扣费/通知界面；成功一项或两项都只扣1AP，完全无工作0AP。

其中“全部适用成体”不包括当日基础分支失败而仍未喂的个体；但早前已由玩家喂过的空闲成体仍可合法投特殊料。基础已喂、特殊缺料的个体补齐后再次维护，只扣特殊料；先前基础服务记录保持原样。

| 本次结果 | 材料与收费 | 显示方式 |
|---|---|---|
| 基础成功＋特殊成功 | 各自实际投入，合计1AP | 基础完成，若干成体已启动周期 |
| 基础成功＋特殊缺料 | 只扣基础料，1AP | 基础完成；特殊未启动，列缺料 |
| 基础已完成＋特殊成功 | 只扣特殊料，1AP | 沿用今日基础服务；启动周期 |
| 未喂对象基础缺料，但先前已喂成体可启动 | 只扣合法成体特殊料，1AP | 分别列未喂对象及已启动对象，不报成全场维护完成 |
| 基础成功＋暂不生产/无适用成体 | 只扣基础料，1AP | 基础完成；新周期已关闭/无启动对象 |
| 基础已完成＋暂不生产/运行中/待收 | 无扣料、0AP | 今日无需新增服务，不作为成功工作 |
| 基础与特殊均未有效执行 | 无扣料、0AP | 明确失败或无对象原因 |

只读报价用临时计算判断分支，不调用实际投喂。实际执行再次检查UID、计划和库存，不能使用过期预览强行扣料。手动与后续雇工共用该事务；雇工合计一次成功工作1元石、不耗玩家AP，具体调度在P7.d另行问答。

## 5. 收取、清退与重试

### 5.1 设施级收取

一次手动收取处理该设施所有待收个体，成功1AP，空闲/幼体/未完成周期保留不动。先计算完整对象及主副产物，校验输出库存不会越界，再原子入库并更新个体：羊清除已收周期，鱼移除对应个体。

羊剪毛后不免费开启新周期；鱼出塘后不免费补苗或重置水体。无待收对象、失效设施或重复请求均0AP、无产物。正常收取沿用成熟采收的直接执行方式；悬停/报价明确“出塘移除成体，不能回退”，清退仍需确认。

每次周期有唯一ID。按钮请求绑定设施UID及报价时的待收“个体UID＋周期ID”集合，执行时核对当前全部待收集合；目标变化需刷新报价，不静默收取另一轮或另一批。已收的周期不能再次入库，界面重建/读档/保存重试也不恢复旧权益。

### 5.2 清退

清退确认列出在养数量、将放弃的待收产物和已投入的运行周期材料，明确“不退款、不返料、不产物”。确认后整体移除动物及周期，保留设施、配置和水体；不生成副产物，不计销售收入。

特殊料在启动时已真实出库，清退时不重复计一笔材料消耗；待收产物尚未入库，放弃时也不虚构材料出库。另记清退/放弃数量，供后续报告说明经营损失。

### 5.3 保存和失败

继续由统一日结完成一份快照后保存。最后1AP启动或收取时，库存、周期身份和资源账必须先写入，再触发日结；保存失败只原样重试，不重新启动、推进、收取或收费。放弃当天整体回到所属槽保存点，不能仅回滚库存而保留已收周期状态。

## 6. 副产物回流与供货

### 6.1 现有加工配方

| 配方ID | 实际投入 | 产物 | 天数 | 启动/收取 |
|---|---|---|---:|---|
| `culture_algae` | 清水3＋秸秆2 | 藻料6 | 2 | 各1AP |
| `compost_sheep_manure` | 羊粪肥2 | 腐殖土2 | 2 | 各1AP |
| `compost_fish_manure` | 鱼粪2 | 腐殖土2 | 2 | 各1AP |
| `compost_grass` | 牧草2 | 腐殖土2 | 2 | 各1AP |

四条已在P7.a配置，培养及加工底座已可运行；本阶段让动物副产物真正来自已完成并收取的周期。堆肥必须先有粪肥入库、建设合法堆肥箱、投料、等满两日再收取，不能在动物刚进入待收时预先投料。

腐殖土基准成本和供养值沿用V1，不因来自羊粪或鱼粪另生成一种物品或动态价格。回流完成以实际施肥成功为准，不能仅有一张循环示意图或仓库中存着腐殖土就算闭环。

### 6.2 五行、价格与rank

钢绒为金属性合格食材，供养11、卖12；鱼肉为木属性合格食材，供养6、卖9。羊粪肥/鱼粪均卖1，不可供货；是否合格沿用资源配置，不套用“有五行就可供养”。四种产物均不开放直接采购，采购需求仍由种子、幼体和可采购生产投入支撑。

订单规则不变：需求=`12×rank`，必要数量向上取整，回款为必要数量×售价＋向下取整的10%溢价。以下仅作已有公式对拍，不代表普通新档已解锁rank3/5：

| rank | 需求 | 钢绒必要数量 / 回款 | 鱼肉必要数量 / 回款 |
|---:|---:|---|---|
| 1 | 12 | 2份 / 26元石 | 2份 / 19元石 |
| 3 | 36 | 4份 / 52元石 | 6份 / 59元石 |
| 5 | 60 | 6份 / 79元石 | 10份 / 99元石 |

常规经营按原营业收入门槛开放，测试入口可指定1/3/5。四只容量不限制累计库存，rank5需要多轮产出时可积存或使用多座设施；不为了方便验收免费提高rank或产量。

标准成本继续采用P7.a固定4只、及时收取的基准。羊购入及首次育成为建立种群的一次投入，鱼苗每轮出塘都会消耗，计入每轮成本；延迟收取、少量饲养和雇工费用记实际账，不改材料静态供养值。

## 7. 资源一览与必要状态展示

特殊周期启动时记录真实补料出库；日结完成只增加待收权益；收取时主副产物各计一次真实入库；销售/供货计材料出库及现金收入。沿用P7.b当日实际与7日均值，两者不混入尚未领取的产量。

养殖详情按“幼体、成体空闲、周期进行、待收”汇总，展开最多4个个体。周期进行显示有效进度及今日是否具备推进条件，待收显示完整主副产物，特殊栏显示当前计划；若计划已停而旧周期运行，明确“已停止新周期，现有周期继续”。

维护报价列基础与特殊分支对象/投入，收取报价列会保留的羊或会移除的鱼。原料不足、只喂基础、暂不生产等结果分别提示，不能一律显示“维护成功”掩盖未启动对象。图标保持小尺寸，悬停说明成本及失败原因。

预计完成日期只针对实际已启动周期，按剩余有效日并标注“连续正常维护时”；缺基础料/低水时显示暂停原因，不承诺固定完成日。关闭新周期不取消旧周期预测，未启动的成体不凭食谱选择就生成待收量或确定日期。

本批提供运行所需详情和资源信息，完整条目式日/时节报告、45天回顾及主界面关注条在P7.e统一设计；不为本批重复改造管理窗口布局或生成正式美术。

## 8. 周期记录与存档建议

继续扩展P7.b拟建养殖模块，复用设施UID与个体UID，不把动物生产塞入现有加工`batch`。下列为拟建数据，尚未写入运行代码：

```text
habitat新增:
  production_enabled: bool      # 特殊栏是否允许新周期
  special_diet_id: String       # 暂不生产时仍保留合法食谱
husbandry新增:
  next_cycle_uid
individual新增:
  cycle: {}                     # 空闲时无周期
     或 { uid, diet_id, start_day, inputs, outputs,
          progress, goal, status(running|ready), ready_day }
```

启动时冻结实际特殊食谱、投入、周期目标和完整主副产物；读取时仍与该物种合法规则核验，不能让存档自定义更高产量。计划关闭或更换不改`cycle`。`ready_day`未就绪时为-1，完成时记录零起始服务日D；日结保存点为D+1，符合P7.b日期口径。

快照校验除P7.b容量/服务/设施关联外，还需覆盖：周期UID全局唯一与计数器、仅成年可有周期、进度/目标/状态一致、投入与产物完整合法、开始/就绪日不越界、待收权益不重复。当前计划关闭或与当前周期食谱不同可以是合法存档，不能因此重置周期。

P7.b拟议schema8尚未实现；P7.c加入新契约后，在实施时依据最终快照结构递增版本，不提前宣称某个后续版本已存在。开发阶段不迁移旧档、不静默填入新周期，三槽/日自动保存/失败阻断照旧。
