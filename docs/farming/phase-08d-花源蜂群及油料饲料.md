# Phase 8.d — 花源蜂群及油料饲料

> 日期：2026-10-11。状态：**已实施并验收通过（2026-10-11自动验收；见§7执行记录）。** 前置：[P8.c](phase-08c-研究系统与依赖导航.md)及共享事务/调度。配数：[资源表](phase-08-资源与工艺表.md)§2～5。下游：[P8.e](phase-08e-污水净化与藻料回流.md)；补光/灵食应用留[P8.g](phase-08g-自动维护补光及五行灵食.md)。

## 1. 本阶段范围和体验路径

实装蜜铃灌木、油籽花、蜜盏蜂、蜂箱、农产加工台；普通配方R01～R07、堆肥V01/V03，陆养/水养复合食谱。T01/T02/T03/T06在正常经营中可达，研究样本必须真实种植、采花、采蜂蜡、榨油取得。

玩家先用T01种植，花期手采花蜜/花粉作为T02样本；建蜂箱购幼群，在附近留足花源。油籽成熟收获、榨油/磨粉，蜂群产蜂蜜/蜂蜡再进入精制与饲料。花瓣、蜂蜜、精炼蜡的厨房消费者留g，期间可按资源表出售；精炼油设备用途留g。

蜂群数量是群标准单位，同箱单物种最多4群，幼群计数，不模拟单蜂/搬运/繁殖。采购预检费用/空间/研究，购入不免费成熟或自动维护。

## 2. 植物生长与花源资格

蜜铃灌木留株成熟后供花，采花不重置生长/制造种子；清理仍为玩家明确的移除动作。油籽花是一轮收获移除，生长进度达到资源表花期区间才供花，缺水低肥沿用降效不死亡。成熟后不继续供花，种实收获与采花是不同动作。

花源资格由当前生长阶段、环境及覆盖判断，不能仅看物种名称。标准正常环境与数量从资源表读取，后续设备有效光照从P8.g同一查询接口接入，不维护第二套自然光算法。

每株UID＋服务日保存份额上限、已使用数量和来源记录。当天首次符合供花资格时初始化上限一次；暂时缺水仅暂停未用份额，恢复不补发。清理后同格重种生成新UID，新苗不符合花期，不继承旧株已成熟条件。未用份额次日失效，不变成仓库物品。

源株同日已采收/清理后仍保留其当日消费收据到日账关闭；验证历史消费不要求源株仍在地图或仍处花期。份额上限和消费时身份来自收据，不能按当前已移除/缺水状态重算出一份新额度。

## 3. 手采、蜂群和授粉事务

| 行为 | 预检与执行 | 资源账 |
|---|---|---|
| 手采花源 | 当前合格、剩完整份额、1AP；扣份额再发花蜜/花粉 | 实际入库，采花动作记录 |
| 蜂群维护 | 合格附近份额＋清水、未服务单位、实际工作费用 | 清水实际出库，花源为内部流 |
| 授粉登记 | 只有蜂群真正成功利用了对应株份额 | 一轮作物布尔标记，不发额外库存 |
| 油籽花收获 | 沿用成熟/AP预检，加一次上限内授粉产量 | 收获时才入油籽/花瓣，移除原株 |

蜂箱范围按占地外扩，来源按株锚点判断。多箱/多群按统一稳定候选顺序分配当前剩余，玩家已手采自然减少可用量；没有“箱子各自复制一份花源”。剩余不足时可服务部分完整单位，稳定轮转并列未服务单位/原因，不能扣半份清水或凭空欠花源。

每个被服务群对应一份真实花源与一份清水；失败无花源/材料/AP/工资变化。写来源份额、群服务日、内部生态事件及清水账必须在触发最后AP之前完成。手采不授粉，蜂群利用才给油籽花本周期标记；蜜铃不增发每日份额，多次/多箱不叠加种实增益。

仓库花蜜/花粉用于样本、销售和合格食材供货，不能替代此阶段蜂群附近花源。地格“采花”动作明确区分种实收获；若接雇工农务，须独立启用采花类别与指定区域，防止原收获委托意外吃光蜂源。

## 4. 蜂群生命周期与在制批次

幼群仅在成功基础维护的服务日成长，达到目标后原群变成体。成体按配置开启产蜜轮，一次设施启动1AP，可选合格空闲群；开启仅登记周期，不提前扣未来日的花源/清水。不自动从仓库借花蜜。

每服务日每群最多推进一次，成长、成熟转换和产蜜不能同一天连续算多个有效日。产蜜缺花源/水/工作暂停，保留进度；完成后待收取，收取1AP/箱、按实际待收群发蜂蜜/蜂蜡并留群。待收群不再接受无进度的重复收费维护。

持续生产复用P8.b目标与在制量，选蜂蜜或蜂蜡作主要成品；只为实际选中群登记预计产出。投料/维护/收取都是同一负责人账户，箱内4群的一次整体维护不是4次工资。

## 5. 农产加工与饲料

R01～R07用普通加工模型，投料时完整扣款/材料、记录不可变配方收据；按普通游戏日完成，不要求每日人工维护，启动/收取各1AP。研究T03/T06分别开放基础/精制能力；V01/V03复用旧堆肥箱，不另造设备。

新增复合食谱只作为玩家可选项，按资源表消耗，无强制替换、无未设计成长加成。改食谱保留当天已经实际喂养记录，下一未服务日/新周期才按新餐执行。油饼可加工饲料也可堆肥，两条路线竞争同一库存，不能消费后仍留可堆肥份额。

本阶段审计饲料的标准成本/产能与旧牧草/藻料食谱，确认确有经营用途；若初值没有优势，在数据批调整并重编成本，不能给未确认的速度或饱食度效果补价值。已有静态食材供养值不随玩家更换食谱重算。

## 6. 界面、保存与验证

作物详情显示花期/今日剩余/已授粉和采花报价；蜂箱显示覆盖、合格株数、可用份额、各群阶段及缺口。选择箱子预览范围，不要求角色实体；指派/手动维护/收取入口都清楚标成本。库存一览把实际手采与蜂群内部利用分开。

保存花源每日消费、作物周期授粉标记、群UID/阶段/周期及最后服务/推进日。内部事件可追溯，但有限花源不是可交易库存。异常来源重复或消费超额拒绝恢复，读档不重新授粉/发产物。

| 场景 | 预期 |
|---|---|
| 花期边界、缺水恢复、自然/有效光改变 | 资格正确，不刷新已用份额 |
| 先手采后蜂用、先蜂用后手采、多箱争源 | 同一份额只用一次，失败无半扣 |
| 多群/多箱授粉、清理重种 | 原周期增益有上限，新株无旧标记 |
| 仓库花蜜很多但附近无花 | 蜂群暂停，不能购买绕过 |
| 幼群成熟/成体完成/收取再启动 | 每群每日仅一推进，待收不入库 |
| 最后AP、日结失败重试、改派/切餐 | 来源、日粮、产物和费用不重复 |
